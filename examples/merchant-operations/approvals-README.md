# Offline approval recorder

Run `node examples/merchant-operations/approvals-demo.mjs` after building `@ghostpay/merchant-multisig`. It generates disposable approval keys in memory, queues a fixture-only payout, reloads the account and consumes the local authorization. It prints only a summary and deletes its private temporary directory. It never signs a payment, broadcasts, calls a chain, or sends notifications.

`approvals-store.mjs` provides `initializeApprovals(directory, trustedPolicy)`, `inspectApprovals(directory)`, and `updateApprovals(directory, expectedRevision, action, now)`. Actions are `queue` (canonical exchange), `execute` (digest), or `prune`. A cancel/config is a signed proposal exchanged and queued through the existing library. Revision and queue nonce are distinct: revision prevents stale local writes; nonce is signed protocol state. A simultaneous operation either wins, sees `LOCKED`, or fails `STALE_SNAPSHOT`. The caller must refresh and explicitly re-review its operation after those refusals.

The adapter is opt-in and qualified on Linux/POSIX. Windows is refused. Use a private directory under a trusted, stable parent on a local filesystem that supports exclusive mkdir, descriptor no-follow, atomic same-directory rename and directory fsync. Network shares and hostile writable ancestors are not qualified. Files are regular, single-linked, owned by the process user and mode 0600; the account directory is 0700. Reads use one no-follow descriptor, bounded to 2 MiB even if the file grows. Replacement writes use an exclusive random private temporary file, file fsync, rename and directory fsync. No existing account can be replaced by initialization.

An exclusive `.lock` directory serializes processes. It is never stolen by age or PID probing. A crash leaves the lock; after confirming all writers have stopped, the operator must inspect the current revision and queue before manually removing it. Retained temporary files are not automatically promoted. Corrupt/truncated state fails closed. The SIGKILL qualification suite kills before and after write, file fsync, rename and directory fsync: reopening sees the previous or newly replaced snapshot, and the retained lock prevents an automatic second decision. This proves tested process-crash behavior, not power-loss guarantees of a particular disk/filesystem.

Local `execute` consumes the approval and returns a proposal after its state commit. There is deliberately no funds-moving callback. If a process crashes after commit but before the caller sees the result, it must inspect the state; it must not infer that any payment happened. A future transaction adapter needs its own durable outbox/submission identity and uncertain-outcome reconciliation. A rollback to an earlier valid snapshot can re-enable a consumed proposal: the revision, signatures and local JSON are not an independent rollback authority.

The package validates persisted signatures, policy/version, nonce, proposal content and clock relationships, including at execution. Operators must still authenticate the initial/current account policy and trust the host clock/storage. Arbitrary state imports are not accepted as updates to an existing account. This recorder does not enforce approvals against an on-chain key holder.

Run the local tests with `node --test examples/merchant-operations/approvals-store.test.mjs`. Test scopes include actual child-process queue/execute races, SIGKILL boundaries, retained locks, changed/stale revisions, corrupt state, file permissions and symlinks. They use disposable local fixtures only.
