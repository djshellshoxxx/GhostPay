# GhostPay for Shopify (skeleton, documentation only)

Shopify does not let ordinary apps add a new checkout payment gateway: that needs the Payments Partner program (offsite payments app) and Shopify's review. This folder therefore describes the realistic non-gateway options and ships one Liquid snippet. Nothing here was run against a store.

## Option A: payment-link app (no gateway approval)
Components, all merchant-hosted:
1. **Invoice service** (same contract as `integrations/woocommerce/README.md`): signs invoices and returns `{invoiceId, link}`. Holds the only signing key.
2. **Embedded app backend** (Shopify CLI Node/Remix template, not included). Flow: merchant creates a draft order (or order with a "Pending" manual payment method); app calls the invoice service with `amountMinor` computed from the order total using decimal-string math in the GhostPay app's minor units of the currency (0 decimals for JPY, KRW, VND, CLP, ISK, UGX, XAF, XOF and 2 for every other code, three-decimal currencies such as KWD included: the table of `GhostPay_Money::currency_minor()` in the WooCommerce and PrestaShop plugins), never Shopify's own currency exponent, refusing a total that needs more decimals; webhook amounts are compared in the same units; app stores `ghostpay.payment_link` as an order metafield (definition: `order`, namespace `ghostpay`, key `payment_link`, type `single_line_text_field`, **not** storefront-readable in public APIs; expose to the customer only through the order status/customer account extension or the invoice email you send).
3. **Webhooks in**: (a) Shopify `orders/*` webhooks: verify `X-Shopify-Hmac-Sha256` = base64(HMAC-SHA256(app secret, raw body)) with a constant-time compare before parsing; (b) GhostPay webhooks: reuse `verifyWebhook` + `parseWebhookEvent` from `@ghostpay/merchant-hooks` (see `examples/webhook-receiver`). On `invoice.paid`/`invoice.over` with `amountMinor >= due` and matching currency, call the Admin GraphQL `orderMarkAsPaid` mutation (needs `write_orders`) for an unpaid order only; for an order that is already paid, flag a possible double payment for a refund instead. Idempotent on GhostPay event id: acknowledge a redelivery only after the first delivery was handled, and answer one that arrives while it is still being handled with a retryable `503` (`IdempotencyGuard`, see `examples/webhook-receiver`); Shopify delivers webhooks at least once.
4. **Scopes**: request only `read_orders`, `write_orders` (and `write_draft_orders` if you use drafts). No customer PII scopes.
5. **Secrets**: Shopify API secret, GhostPay webhook secret and signing key live in the app host's secret store, never in the repo or theme.

## Option B: theme snippet only
`snippets/ghostpay-button.liquid` renders a static button from a link you generated yourself (email, order metafield). It checks https, exact host, no query/credentials and the `#gpi=v1.` fragment, and escapes the label. Theme setting `ghostpay_pay_host` goes into `config/settings_schema.json` as a text input. Do not put payment links in public theme assets, product pages or anything cached for other visitors.
