# Deviations and open points (@ghostpay/confidential-contracts)

Evidence tags: [R] read in this repo or in the installed npm packages, [E] executed here, [U] unverified.

## Tooling

1. **Hardhat, not Foundry.** The fhEVM mock execution is the `@fhevm/hardhat-plugin` / `@fhevm/mock-utils` JS runtime [R]; no Foundry equivalent was found [U]. `foundry.toml` exists only so `forge fmt --check contracts` works; it is not used to build. The package is CommonJS (no `"type": "module"`) because Hardhat 2 loads its config with `require`.
2. **Local solc.** Hardhat 2 downloads compilers from binaries.soliditylang.org (blocked in the sandbox). `hardhat.config.ts` overrides the compiler only when `GHOSTPAY_SOLC_PATH` is set; the path is never committed.
3. **Version set (spike S-1, resolved) [R][E].** `@openzeppelin/confidential-contracts 0.5.3` pins `@fhevm/solidity` **0.11.1** exactly; `@fhevm/hardhat-plugin 0.4.2` peers `@fhevm/solidity ^0.11.1`, `hardhat ^2`, `@fhevm/mock-utils 0.4.2`, `@zama-fhe/relayer-sdk 0.4.1` (a deprecated package, kept only because the plugin requires it) and depends on `@fhevm/host-contracts 0.10.0`. So the spec's candidates `@fhevm/solidity 0.13.4` and plugin `0.13.0-1` are **not** used. Pinned: hardhat 2.29.1, ethers 6.17.0, `@openzeppelin/contracts 5.6.1` (same as `packages/contracts/lib`). Config contract is `ZamaEthereumConfig` in `@fhevm/solidity/config/ZamaConfig.sol` (0.11.1), reverting `ZamaProtocolUnsupported` outside chains 1, 11155111, 31337.
4. **The plugin rewrites compiled sources [E].** The Hardhat build-info shows `ZamaConfig.sol` compiled with absolute imports and a different local-chain `KMSVerifierAddress` than the file on disk. Only the chain-31337 branch differs; the Sepolia branch is unchanged. Before any Sepolia deployment, compile without the mock plugin or diff the bytecode.
5. **Slither** cannot read the Hardhat build (the rewrite above breaks source maps), so it was run with solc directly and import remappings (command in the audit doc).
6. **SPDX.** Router, token and mocks are `UNLICENSED` like the repo; they import BSD-3-Clause-Clear (`@fhevm/solidity`) and MIT code. Zama's README says commercial use needs a Zama patent licence (legal deferred by the owner).

## Contract deviations from the spec (section 6.1)

1. **Constructor takes a fixed token list**: `(announcer, feeRecipient, IERC7984[] tokens)`, 1 to 8 distinct tokens, and `payConfidential`/`flushFees` revert `TokenNotAllowed` for others. Reason: the router grants `allowTransient` on router-computed handles to the token it calls; with a caller-chosen token a malicious contract could persist that access (`FHE.allow`) on handles derived from the router's fee balance, learning the aggregated fees. Extra errors: `TokenNotAllowed`, `InvalidTokenList`, `UnsupportedChain`.
2. **`epochStart` replaces `lastFlush`.** The epoch of a token starts at the first payment after the previous flush (0 when nothing is pending); `flushFees` needs `FEE_EPOCH` since then and resets it. With the spec's `lastFlush` (time of the last flush), a payment after a long idle period could be flushed in the same block by anyone, giving the fee recipient that single fee (a test, `a payment after an idle period cannot be flushed on its own`, covers it). `flushFees` with nothing pending reverts `FlushTooEarly`.
3. `fallback` is `payable` and reverts `NoDirectETH` (spec: revert). No behavioural difference.
4. `SCHEME_ID`, `MAX_TOKENS`, `isTokenAllowed`, `epochStart` are public getters (not in the spec text).
5. The router holds an encrypted fee balance between flushes (spec already notes this deviation from CONTRACTS_SPEC).
6. Spec step 2 says `FHE.allowTransient(gross, token)`; ACL of op results was [U] in the spec. Resolved [E]: `FHE.div`/`FHE.sub` results are usable by the calling router, `FHE.allowTransient(net, token)` is needed and sufficient, and `token.confidentialTransferFrom` leaves `t` allowed to the router (as recipient and via transient allow).

## Tests: what ran [E] and what is not proven

- `npx hardhat test`, mock fhEVM, 46 tests (T1 unit, T2 zero-balance, T3 event scan, CT-C-3 fee-split fuzz, multi-actor conservation checks, wrap/unwrap/finalizeUnwrap, anvil-based chain guard on chain ids 1, 10, 137, 8453, 42161, 84532, 11155420 (refused) and 31337, 11155111 (allowed)).
- **"Fuzz" and "invariants" are seeded randomised Hardhat tests**, not Foundry fuzz/invariant runs, with a hand-written model: 1000 random payments in one deployment, 11 boundary amounts (0, 1, 399, 400, 401, 799, 800, 10^6, 2^63, 2^64-2, 2^64-1) in fresh deployments, 4 sequences of 40 random wrap/pay/flush steps checking conservation (sum of all balances plus router plus recipient equals the decrypted total supply) after every step. No Echidna or Foundry invariant campaign.
- **Mock only.** Everything above runs against `@fhevm/mock-utils` (plaintext coprocessor). It does not test real ciphertexts, real ACL contract events, the KMS, gateway or coprocessor limits. **T9 (live Sepolia) was not run**: no network access to RPC or relayer, no funded key. Sepolia deployment, user-decrypt latency (spike S-2) and `finalizeUnwrap` latency are [U].
- **Gas and HCU (mock executor, solc 0.8.28, optimizer 200)** [E]: `payConfidential` 800,499 gas (cold stealth), 735,391 (second payment to the same stealth); `flushFees` 342,114 gas. HCU (`fhevm.computeTransactionHCU`): `payConfidential` global 2,049,128, depth 1,453,000; `flushFees` global 586,064, depth 369,000. The Zama per-transaction HCU limits (I recall 20,000,000 global and 5,000,000 depth) are [U]; not verified from a primary source here. Mock gas does not equal Sepolia gas.
- **Echidna 2.3.1** (GitHub release binary) was obtained and run [E] on `echidna/EchidnaConfidentialRouter.sol`; it compiles but **cannot deploy the router**: Echidna 2.3.1 has no chain-id option (chain id 1) and the router constructor correctly reverts `UnsupportedChain(1)`. Also, Echidna's EVM has no fhEVM host contracts, so only validation order, the ETH invariant and the flush gate could ever be fuzzed there. The harness is therefore unrun; the FHE-dependent properties are covered only by the Hardhat tests above.
- **Slither 0.11.6** [E]: no high/medium. Router: `timestamp` (intended: deadline and epoch) and `naming-convention` (immutables in caps, same as the existing router) remain; `unused-return` on `FHE.allow*` and `missing-zero-check` (stealth checked in `_validate`) are suppressed inline with justification. Token and `MockERC20`: 0 results. Mocks and `ReentrantStealth` not analysed.
- CT-C-9 (HCU margin) cannot be closed without the Sepolia limit [U].
- `npm run build` in other workspaces does not run this package's compile (`compile` is a separate script name) so a root `npm run build` does not need a solc download; `npm test` at the root does (full suite, ~6 min). Decide in CI whether to run `test:quick`.
