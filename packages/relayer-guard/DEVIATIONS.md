# Deviations and open points (@ghostpay/relayer-guard)

1. **Not integrated.** `apps/relayer` still uses its own `breaker.ts`/`limiter.ts`; this task was not allowed to edit apps. Integration steps are in the spec, section 6.
2. **Probe timeout counts as failure** (re-opens, cooldown from the expiry instant). The relayer runbook describes an in-progress fix as "probe timeout that re-opens the breaker"; this matches that description, but the in-progress code was not seen.
3. **Broken forwarding chain returns `null`** instead of falling back to the proxy address, to avoid the shared-bucket self-DoS described in S3-07. The caller must answer 400.
4. **Overflow bucket** is shared by all newcomers while the table is full of active keys (availability over per-client fairness during a flood).
5. Classification of mined reverts (`mined_revert_state_changed` vs `mined_revert_unexplained`) requires a re-simulation the relayer does not do yet.
6. Primary RFCs (7239, 6585, 9110) could not be fetched in this session; behaviour is based on the MDN pages cited in the spec.
7. **Challenge: `context_mismatch` dropped.** The context is inside the MAC, so a wrong context is indistinguishable from forgery and reports `bad_signature`; distinguishing them would be an oracle.
8. **Challenge: store-full signalling.** `ReplayStore.markUsed` keeps its `boolean` contract; "full" is signalled by throwing (`ReplayStoreFullError`), and any throw maps to `replay_store_full` (fail closed). `AttemptLimiter` signals full by returning `Infinity`; a throw maps to `too_many_attempts`.
9. **Challenge: unexpected internal errors** in `verify` (e.g. a throwing clock) are reported as `malformed` rather than thrown.
10. **Challenge: difficulty is bound into the MAC**, so changing it invalidates outstanding tokens. Memory stores are per-process only.
11. **Round-audit fixes (M-1..M-4, L-7, L-8), all additive and backward compatible.**
    - **M-1 challenge stores.** `verify()` takes an optional `partition` (client bucket, never logged); `ReplayStore.markUsed` / `AttemptLimiter.increment` get an optional third `partition` argument. Memory stores enforce a per-partition quota (`maxPerPartition`, default `maxEntries/8`; unpartitioned entries have no quota, so old callers see old behaviour). Deviation from the guidance: an over-quota partition fails closed for itself in the attempt limiter (no eviction of its own tokens, which would hand the flooder free guesses); only a globally full table evicts, the oldest entry of the largest partition. The replay store never evicts and throws only for the over-quota partition or a completely full table (needs >= 8 colluding partitions each solving challenges). `issue()` stays unauthenticated and uncapped: callers MUST rate-limit it per client.
    - **L-7.** Expired entries are reclaimed from the front of the insertion-ordered map (O(1) amortised) and a full scan runs at most once per second when the table is full, so a flood cannot force O(n) work per insert.
    - **M-2.** `LossBudget.reserve/settle/release` (atomic, synchronous). `allows()` is advisory. `settle` may record an actual cost above the estimate (real loss is never hidden), so totals can exceed a limit by the estimate error; a reservation from an earlier window is ignored on settle. Estimates must be worst case.
    - **M-3.** `TokenBucketLimiter` options `groupOf`, `maxPerGroup` (default `maxKeys/4`), `maxOverflowGroups` (default 1024) and `stats()`. Without `groupOf` behaviour is unchanged (one global overflow bucket, item 4 still applies there). New `groupKey` / `groupOfBucketKey` in `ip.ts` (IPv6 /48, IPv4 /24). A saturated group can only evict its own idle entries. Per-group overflow is itself bounded; beyond that the global bucket is the last resort. **L-8:** eviction scans the 8 oldest entries for an idle one.
    - **M-4.** `tryAcquire({ validated })` and `maxNeutralProbes` (default 5). Default behaviour changed in one place: `retryAfterMs()` is now nonzero (1..1000 ms, capped by the probe timeout) while a probe is in flight, and legacy callers (no `validated`) lose the probe after 5 consecutive neutral probe settles in an episode until a validated caller takes it (the existing test asserting 0 was updated). The breaker cannot be forced open by neutral outcomes and still never wedges: a probe timeout re-opens it.
