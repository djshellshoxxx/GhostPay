# @ghostpay/chain-adapters

EVM chain adapter for GhostPay (ESM, strict TypeScript, viem). It turns a validated invoice into a checked router
transaction, scans ERC-5564 announcements safely, signs gasless sweeps and talks to RPC/oracles fail-closed.
Crypto is reused from `@ghostpay/core-crypto`; no key material is created or exported here.

| Module | Purpose |
|---|---|
| `config/chains.ts`, `config/tokens.ts` | Chain table (testnets enabled, mainnets `enabled:false` until a manifest exists) and verified-only token allowlist |
| `fees.ts` | `FEE_SCHEDULE`, `routerFee/Net/Split`, `grossForNet`, `calculateBuffer`, `sponsorFee`, flat-fee config |
| `deployments.ts` | Strict manifest loader (`deployments/schema.json` + extra rules) |
| `abi/*.ts` | Const-asserted ABIs, generated by `scripts/gen-abi.sh` |
| `router.ts` | `buildPaymentTx`, `decodePaymentCalldata`, `assertPreviewMatchesCalldata` |
| `sweep.ts` | EIP-712 `Sweep` + ERC-2612 permit typed data, digests, noble signing |
| `rpc.ts` | Verified client (`eth_chainId`), URL policy, timeout, size cap, jittered retry, provider cross-check |
| `logs.ts` | Paginated, reorg-safe `Announcement` fetch with strict validation |
| `quote.ts` | Chainlink read + fiat-to-token conversion (payer rounds up) |
| `adapter.ts` | `ChainAdapter` interface and `createEvmAdapter` |
| `readback.ts` | `verifyManifest` / `assertManifestVerified`: manifest vs chain (fee recipient, announcer, fee bps, code hashes), fail closed |
| `verify.ts` | `verifyAnnouncementAmount`: `verified` vs `claimed` amounts for detected payments |
| `registry.ts`, `abi/erc6538.ts` | ERC-6538 registry ABI, `buildRegisterKeys` / `buildClearKeys` / `buildRegisterKeysOnBehalf` / `buildIncrementNonce`, `lookupMeta`, `assertRegistryAvailable` |

## Usage sketch

```ts
const manifest = loadDeployment(text, 84532);               // throws on anything unexpected
const client = await createClient(findChain(84532)!, rpcUrl); // verifies eth_chainId
const adapter = createEvmAdapter({ chain, deployment: manifest, client });
const req = adapter.buildPaymentRequest(invoice);
const { tx, preview } = req.build({ deadline });
assertPreviewMatchesCalldata(preview, tx, 84532);            // before the wallet prompt
```

## New API (2026-10-21)

```ts
// 1. Manifest read-back: call before enabling payment, pass the result to the adapter.
const rb = await verifyManifest(manifest, [primaryClient, secondClient], { requireTwoProviders: true });
assertManifestVerified(rb);                       // throws MANIFEST_READBACK_FAILED naming the failed checks
const adapter = createEvmAdapter({ chain, deployment: manifest, client: primaryClient, readback: rb,
  secondaryClient: secondClient, minConfirmations: chain.finalityDepth, onReorg: (n) => dropMatchesFrom(n) });
// 2. scan() yields DetectedPayment with: verification ('verified' | 'claimed' + reason), confirmations, final.
//    Show an amount as received only when verification.status === 'verified'.
// 3. ERC-6538: buildRegisterKeys(meta) -> TxRequest { to: REGISTRY_ADDRESS, data, value: 0n }; lookupMeta(client, addr).
//    Gate the UI with assertRegistryAvailable(client, pinnedCodehash). Publishing is a public association.
// 4. adapter.fees.flatSecurity now reflects manifest.policy.
// 5. Quotes: readPrice(reader, feed, { now, maxAgeSeconds, heartbeatSeconds, sequencerUptime: { feed } }),
//    assertSequencerUp, effectiveMaxAge, withinSlippage.
// 6. fetchAnnouncements({ ..., minConfirmations, secondary }) -> also returns head, scanHead; announcements carry
//    confirmations and transactionHash. requestWithFallbackCheck gained an optional projection argument.
```

New error codes: `MANIFEST_READBACK_FAILED`, `REGISTRY_UNAVAILABLE`. Known limits: DEVIATIONS 14-18.

## Safety rules enforced here

- Fee recipient only from the manifest; no address constants in source. Mainnets stay disabled.
- Router math is bit-identical to the contract (floor 25 bps; `gross <= max/25`).
- Any mismatch between the previewed payment and calldata (token, stealth, gross, fee, net, minNet, deadline,
  metadata, ephemeral key, router, value, buffer cap, permit) throws `PREVIEW_MISMATCH`.
- RPC: https/wss only (loopback http needs an explicit flag), credentials in URLs rejected and never echoed,
  response-size cap, bounded retries, chain id verified before use.
- Logs: provider faults throw, hostile content is skipped and counted; cursors store a block hash and roll back by
  `finalityDepth` on mismatch.
- Quotes: stale, non-positive, earlier-round or future answers are refused.
