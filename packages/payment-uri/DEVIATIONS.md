# Deviations and open points (@ghostpay/payment-uri)

1. **Not integrated.** No app calls this package yet. The web app's `paymentUri()` (`apps/web/src/features/btc/wallet.ts`) still uses `btc-silent-payments`. Camera/QR scan routing is the integrator's job.
2. **Spec examples that fail strict parsing.** The EIP-681 example `0xfb6916095ca1df60bb79Ce92ce3ea74c37c5d359` has an invalid EIP-55 checksum, and the BIP-21 example `175tWpb8K1S7NmH4Zx6rewF9WQrcZv245W` has an invalid base58check checksum. Both are rejected by design (tests cover this); the all-lowercase EIP-681 form is accepted and flagged `checksummed:false`.
3. **Stricter than the specs:** duplicates of any key are rejected (BIP-321 allows repeated payment instructions); unknown parameters are rejected for EIP-681, Solana Pay and TRON; unknown optional BIP-321 keys are dropped and reported by key; raw `+`, empty values and non-ASCII are rejected; zero amounts rejected; EIP-681 negative/`+` numbers and ENS names rejected; all-uppercase EVM hex rejected; BIP-352 only version 0.
4. **EIP-681 scope:** only native transfers and `transfer(address,uint256)`. `pay-` prefix accepted and flagged. Other functions, typed parameters and `value` on token transfers: rejected. Chain id capped at 2^53-1. Missing chain id is accepted unless `expectedChainId` is set.
5. **Bitcoin:** `lightning=` (BOLT11) is charset/length/network-prefix checked only, NOT decoded or verified. `pop`, `lno`, `pay` are ignored, `req-pop` is rejected. Testnet and signet share prefixes (`test`); `tsp` and `lntb` cannot tell testnet from regtest.
6. **Solana Pay:** transaction requests (`solana:https%3A...`) unsupported. Amount is returned as exact `Decimal` in whole units; the caller supplies mint decimals to `solanaAtomic` (u64 bound). Spec text was not fetchable from the official site in the build sandbox; rules were taken from the `@solana/pay` 1.0.26 `parseURL` source plus the published README, and `reference` repeat limit (8) and label/message/memo byte caps (128/512/256) are GhostPay choices.
7. **TRON:** NONSTANDARD. `tron:<T-address>?network=&amount=&token=&label=&message=` is invented here; other wallets will not read it. No signature or checksum beyond base58check.
8. **ERC-3770** short names come from a small built-in table copied from ethereum-lists/chains (15 chains); callers can pass a larger registry. No ENS.
9. **Lookalike detection** is not done here: only canonical form, display grouping and a 48-bit digest are returned. Mixed-script is per-word Latin vs Cyrillic/Greek only; same-script homoglyphs are not detected.
10. **Invoice link** is checked structurally only (host charset, no userinfo/query, base64url alphabet); the envelope is NOT decoded, authenticated or length-checked against 16384 bytes, which `@ghostpay/invoice-schema` does. `FRAGMENT_PREFIX` is duplicated (no cross-package import). Passphrase-protected links use the same wrapper.
11. **Single-QR capacity:** links and URIs above ~2.9 KB do not fit one QR; use `@ghostpay/qr-exchange` multipart.
12. **Not done:** no ADR-LOG entry (outside owned paths); no browser or device test; `dist` only built locally.
