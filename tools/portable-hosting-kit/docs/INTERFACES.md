# Portable hosting kit: module contracts (frozen for parallel work)

This file is the contract between modules. Shared files (`src/errors.mjs`, `src/types.mjs`, `src/policy.mjs`,
`src/version.mjs`, `package.json`, `tsconfig.json`, `eslint.config.mjs`, this file) are owned by the coordinator.
Workers do not edit them; if a contract is wrong, report it instead of working around it.

Language: Node.js >= 22 ESM `.mjs`, `// @ts-check` + JSDoc types (strict `tsc --checkJs`), **no runtime
dependencies** (standard library only). Tests: `node:test` + `node:assert/strict`, files `test/<area>/*.test.mjs`.
Fixtures are generated by tests into `fs.mkdtemp(os.tmpdir())` directories (no committed symlinks or binaries).
Filesystem and network boundaries are injectable (an `fs` option defaulting to `node:fs/promises`, a
`createServer` option defaulting to `node:http`), so tests can simulate failures.

Run from `tools/portable-hosting-kit`: `npm run lint`, `npm run typecheck`, `npm test`.
(`eslint`/`tsc` come from the repository root `node_modules`; run `npm ci --ignore-scripts` at the root once.)

## Archive layout (format `ghostpay.hosting-kit.manifest` v1)

A ZIP file (no ZIP64, no encryption, no data descriptors, no extra fields, UTF-8 names) with exactly one top-level
directory `<topDir>/` = `<appId>-<label>` (label sanitized to `[A-Za-z0-9._-]`):

```
<topDir>/site/<every accepted input file, bytes unchanged>
<topDir>/HOSTING-MANIFEST.json   versioned manifest (types.mjs HostingManifest)
<topDir>/OPERATOR.md             operator instructions        (extra file supplied by the coordinator)
<topDir>/EXTERNAL-REFERENCES.json privacy inventory           (extra file supplied by the coordinator)
<topDir>/LICENSES/...            notices                      (extra files supplied by the coordinator)
<topDir>/SHA256SUMS              "<hex>  <path relative to topDir>\n" for every other file, sorted, not itself
```

Next to the archive (never inside it): `<archive>.sha256` = `"<hex>  <archive basename>\n"`.

- `content.files` lists `site/` files with paths relative to `site/`, sorted by UTF-8 byte order.
- `content.digest` = `"sha256:" + hex(sha256(canonicalJson({ entrypoint, files })))`, RFC 8785 canonical JSON.
  It identifies the unpacked content independent of archive container, entry order, compression and timestamps.
- `metadataFiles` = sorted top-level paths other than `site/**` and `SHA256SUMS` (includes `HOSTING-MANIFEST.json`).
- No wall-clock time anywhere. ZIP entries: sorted by UTF-8 name, DOS time 1980-01-01 00:00:00, mode 0644
  (version-made-by Unix), method deflate (zlib level 9) unless store is not larger or `compression: 'store'`.
- Reproducibility claim: the content digest is reproducible from the same input bytes and paths on any platform.
  The archive bytes are reproducible for the same input, options and kit version; with `compression: 'store'` this
  does not depend on the zlib build, with `deflate` it holds for the same Node.js/zlib build.

## Core API (`src/core/*`)

```js
// paths.mjs
validateRelativePath(p, limits) -> { ok: true, path } | { ok: false, rule, reason }
collisionKey(p) -> string            // NFC + toUpperCase().toLowerCase(), for case-insensitive hosts
compareUtf8(a, b) -> -1 | 0 | 1      // byte order of UTF-8 encodings
isInside(parentAbs, childAbs) -> boolean  // child strictly inside parent after path.resolve

// inventory.mjs  -- bounded walk, never follows symlinks (lstat only)
walkSite(siteDir, { limits, fs? }) -> Promise<{ root, files: InventoryEntry[], findings: Finding[] }>
//   global bounds (maxDirEntries, maxFiles, maxTotalBytes) throw KitError(E_LIMIT) immediately;
//   per-file problems (symlink, special file, size, path rules) become error Findings.

// validate.mjs
validateSite(siteDir, { limits?, entrypoint?, allowSourceMaps?, fs? }) -> Promise<ValidationReport>
//   path rules, DENY_RULES, allowlist (MIME_TYPES / ALLOWED_EXACT_NAMES / ALLOWED_HIDDEN_DIRS), collisions,
//   entrypoint exists and is HTML, secret content scan (text files) + magic prefixes (all files),
//   trustSensitive detection (JSON under deployments/ or with chainId + 0x40-hex address fields; informational).
//   Never modifies anything. Response-header checks are NOT done here (see serve/headers.mjs).

// canonical-json.mjs
canonicalJson(value) -> string ; canonicalBytes(value) -> Uint8Array   // RFC 8785 subset; throws on non-safe-integers

// hash.mjs
sha256Hex(bytes) -> string ; sha256File(absPath, { fs? }) -> Promise<string>

// manifest.mjs
contentDigest(entrypoint, records) -> 'sha256:<hex>'
buildManifest({ appId, entrypoint, records, limits, allowSourceMaps, provenance, trustSensitive, metadataFiles }) -> HostingManifest
serializeManifest(manifest) -> Uint8Array      // deterministic JSON, 2-space indent, trailing "\n"
parseManifest(bytes) -> HostingManifest         // strict: unknown schema/version/fields -> KitError(E_VERIFY)

// zip.mjs
createZip(entries: { name, data: Uint8Array }[], { compression: 'deflate' | 'store' }) -> Uint8Array
readZip(bytes, { limits }) -> { entries: { name, data: Uint8Array }[] }   // safe reader, throws KitError(E_ARCHIVE|E_LIMIT|E_PATH)

// atomic.mjs
writeFileAtomic(target, bytes, { fs? }) -> Promise<void>   // temp in same dir + fsync + rename; old file intact on failure
replaceDirAtomic(targetDir, build: (tmpDir) => Promise<void>, { fs? }) -> Promise<void>

// package.mjs
packageSite({ report, outFile, appId, provenance, extraFiles?, compression?, limits, allowSourceMaps, fs? })
  -> Promise<{ archivePath, archiveSha256, sidecarPath, manifest, topDir }>
//   refuses a report with errors, an outFile inside siteDir, extraFiles under site/ or named SHA256SUMS;
//   hashes exactly the bytes it stores (one read per file) and rechecks size against the inventory.

// verify.mjs
verifyArchive(archivePath, { expectedContentDigest?, expectedArchiveSha256?, limits? }) -> Promise<VerifyResult>
verifyDirectory(topDirPath, { expectedContentDigest?, limits? }) -> Promise<VerifyResult>
extractArchive(archivePath, destDir, { limits? }) -> Promise<{ topDir: string, result: VerifyResult }>  // refuses unless ok
// VerifyResult = { ok, manifest | null, contentDigest | null, archiveSha256 | null,
//                  changed: string[], missing: string[], unexpected: string[], errors: Finding[],
//                  authenticity: 'not-established' | 'content-digest-matches-expected' | 'archive-sha256-matches-expected' }
```

## Serving API (`src/serve/*`, `src/profiles/*`)

```js
// headers.mjs  -- Netlify/Cloudflare `_headers` subset: path patterns with "*" splat; "! Name" detach; "#" comments.
parseHeadersFile(text) -> HeaderRule[]            // ":placeholder" and absolute-URL patterns -> KitError(E_HEADERS)
effectiveHeaders(rules, sitePath) -> [name, value][]   // sitePath relative to site root, e.g. "/assets/a.js"
checkRequiredHeaders(rules, htmlSitePaths) -> Finding[] // REQUIRED_HEADERS + REQUIRED_CSP_DIRECTIVES
loadHeaderPolicy(filePaths, readText) -> Promise<HeaderPolicy>   // site `_headers` if present, else KIT_DEFAULT_HEADERS_FILE
transportHeaders(hostConfig) -> [name, value][]   // HSTS only for clearnet https; Onion-Location if configured

// routing.mjs  -- normative request semantics; preview and nginx MUST agree (differential test)
createRouter({ files, entrypoint, basePath }) -> (urlPath) => RouteResult

// preview.mjs  -- loopback only; serves only inventoried files
startPreview({ siteDir, files, entrypoint, basePath, policy, host?, port?, createServer?, fs? })
  -> Promise<{ url, port, close(): Promise<void> }>     // non-loopback host -> KitError(E_NETWORK_SCOPE)

// profiles
exportStatic({ siteDir, files, entrypoint, hostConfig, policy, outDir, overlayFiles? }) -> Promise<{ wwwRoot, files: string[] }>
generateNginx({ files, entrypoint, hostConfig, policy, wwwRoot }) -> { files: { name, data }[] }
generateContainer({ hostConfig, nginxFiles }) -> { files: { name, data }[] }
```

Routing semantics (normative):

1. Only GET and HEAD; anything else -> 405 with `Allow: GET, HEAD`.
2. The path is percent-decoded once; invalid encoding, NUL, backslash, or a "." / ".." segment -> 404.
3. Path equal to the base path without its trailing slash -> 301 to the base path. Outside the base path -> 404.
4. A segment starting with "." (except a first segment `.well-known`) or a name in NEVER_SERVED_NAMES -> 404.
5. Relative path ending in "/" (or empty) -> try `<rel>index.html`.
6. Exact file -> 200 file. A directory containing `index.html` requested without trailing slash -> 301 to add it.
7. Otherwise, if the last segment has no "." -> 200 with the entrypoint (SPA deep link). Else 404.
8. Headers: effective `_headers` rules for the served file (the entrypoint for deep links), `Content-Type` from
   `policy.contentTypeFor`, `Cache-Control: no-cache` unless a rule sets it, transport headers. 404/405/301
   responses carry the rules that match the requested path (at least the `/*` security headers).

## Host configuration (`src/config/host-config.mjs`, coordinator)

`parseHostConfig(json) -> HostConfig` (types.mjs). Listeners are loopback TCP (`127.0.0.1`, `::1`) or a unix
socket path; anything else is `E_NETWORK_SCOPE`. Fields that look like secrets or app trust settings (keys,
seeds, tokens, chain IDs, contract addresses, RPC URLs) are rejected with `E_CONFIG`.

## Transport adapters (`src/adapters/*`)

```js
generateTorProfile({ hostConfig, hiddenServiceDir, target, virtualPort?, instance?, powDefense?, forbiddenRoots? })
  -> { files: { name, data }[], warnings: string[] }
generateI2pProfile({ hostConfig, router: 'i2pd' | 'java-i2p', tunnelName, target, keysFile, inport?, forbiddenRoots? })
  -> { files: { name, data }[], warnings: string[] }
```

Both are pure generators: they never start daemons, create keys or directories, or touch system configuration.
Identity/key paths must be absolute (Tor) or router-relative (I2P) and must not lie inside any `forbiddenRoots`
(site, export or archive output directories).
