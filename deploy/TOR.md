# Tor onion service (compose profile `onion`)

`docker compose --profile onion up -d` (or `selfhost.sh --onion`) builds `deploy/tor/Dockerfile` (Debian `tor` package) and runs it with `deploy/tor/torrc`: v3 hidden service, port 80 forwarded to `web:8080`, `SocksPort 0`, `ControlPort 0`, logs to stderr, no non-anonymous mode.

- **Keys**: generated by Tor on first start inside the `tor-data` named volume. Nothing is in the repo (`.gitignore` also blocks `tor-data/` and `*.key`). Back up the volume if you need a stable address; anyone with it can impersonate your onion.
- **Address**: `docker compose exec tor cat /var/lib/tor/ghostpay/hostname`.
- **Origin**: onion is plain HTTP inside Tor (authenticated by the address). Add the `http://<addr>.onion` origin to the relayer `allowedOrigins` only if you want the SPA served from it to call `/api/`. The CSP `connect-src 'self' https: wss:` blocks plain `http:` RPC URLs, which is intended.
- **Limits**: web-bundle delivery over Tor does not hide the chain RPC calls a browser makes (user-chosen RPC); see `docs/remote/onion-i2p-research.md`. The server host and its operator remain a trust point. Not tested: image build, bootstrap, reachability.
