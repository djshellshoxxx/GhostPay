## Delivered scope

- The reconciliation ledger now uses catalog keys for its controls, proposals, ambiguity reasons,
  backup previews, privacy/retention disclosures, confirmations, invoice registry and receipt archive.
  Preview counts use complete plural messages. No status, record field, evidence rule, signature,
  amount, timestamp, identifier or backup serialization is translated or rewritten.
- Manual digest and encrypted-backup inputs explicitly remain LTR. Shared `Mono` values have
  `dir="ltr"`; ledger asset/amount values are isolated from surrounding RTL text.
- Fixed public errors in settings, wallet, payment, sweep, scan, encrypted storage, keystore,
  public exchange, tags, invoice creation and reconciliation now carry stable descriptors.
  Existing English `Error.message` diagnostics are retained. Reconciliation validation errors
  are typed public errors; arbitrary storage/RPC exceptions are replaced with a fixed safe message.
- `captureUserMessage` discards arbitrary exception objects/causes immediately and retains only a
  public message descriptor or existing trusted public copy. `displayMessage` renders that value
  using the current translator. Schema errors retain their public field location and translate
  both the base diagnostic and surrounding field message at render time.
- CreateInvoice, Pay, Sweep, Scan, SellerKeys, Settings, Registry and WalletAttempts retain captured
  errors until rendering, rather than freezing `userMessage` output in the source language.
  Already-visible errors can change language without replaying the failed action. Async ledger
  announcements use the latest translator; language changes do not alter pending operation guards.
- The final focused follow-up completes the two passphrase validation diagnostics and three
  sweep replacement/pending guards using descriptors, without changing validation or journal rules.
  `passphraseProblem` retains its source-string API; UI and throwing consumers use the new
  `passphraseProblemMessage` API and never retain the candidate passphrase in a diagnostic.
- Navigation labels use catalog keys while the stable `ViewId` and selected route remain unchanged.
  Six neutral navigation labels translate; key/privacy/test-network/experimental labels stay English.
  Navigation buttons expose their existing route ID as `data-view`, so browser journeys need not use
  source-language text as an identity. Unsubmitted payer-link input remains unchanged and LTR.
- `QrView` renders safe captured diagnostics and auxiliary copy with the current translator.
  Switching languages does not rebuild a QR matrix or alter its payload, and arbitrary exceptions
  use the fixed QR-unavailable message. A reviewed-locale fixture changes an already-visible public
  error without retrying generation.
- Added the policy evidence/deployment/withdrawal lane's requested catalog entries. This worker
  does not own their implementations or claim those policy boundaries are complete.
