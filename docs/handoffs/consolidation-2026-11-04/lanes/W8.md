## Left for the owner

1. **Branch protection on main** is still absent (C6 owner question 2). Integrate is now the only merge gate. It is much stricter, but it still merges without human review. The owner decides whether to keep auto-merge at all.
2. **GHOSTPAY_GITHUB_TOKEN scope and identity** are unknown (see the allowlist section). If the PAT has admin or workflow scope, it can bypass protection added later.
3. **Residual risk in the develop job:** the agent runs in the same job as later steps. It could, for example, plant a `core.fsmonitor` hook in `.git/config`, or write to `GITHUB_ENV`/`GITHUB_PATH` if its `:workspace` sandbox allows that (unverified). With that, it could run code in later steps or reach the runtime cache token, if any step exposes one. The publish-side re-check bounds what reaches a PR. The authoritative fix is to run the agent in a job with nothing trusted after it. Owner or lead decision.
4. **Prompt injection across runs:** `docs/handoffs/*.md`, which the next run reads, is still in the agent's write set (C6 MEDIUM). Parallel-review still writes fork PR titles into `active-pr-ownership.md` (C6-M2 MEDIUM). I did not change either because both are outside the five fixes listed in the brief.
5. **Solidity:** `packages/contracts/**` stays writable by the agent (C6 suggestion 3). Owner decision.
6. **A fork PR named `codex/ghostpay-cloud-*` still pauses the develop job** through the preflight count at :82-83. That only saves credits, so I left it.
7. **Check-run provenance:** required checks are matched by name only. A same-repo PR cannot add workflows under the new policy, but any GitHub App with `checks:write` could post a check with the same name. The owner could add an `app.slug == "github-actions"` filter.
