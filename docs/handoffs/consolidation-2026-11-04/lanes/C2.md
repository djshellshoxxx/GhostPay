## Security-equivalence proof: #40 secret-file race

### The race before the fix (`dfd5cbd:apps/relayer/src/secrets.ts`)

The loader checked the file by path and then read it again by path:
1. `lstatSync(path)`: symlink check.
2. `statSync(path)`: type, size ≤ 4096, `mode & 0o077`, owner.
3. `readFileSync(path)`: re-opens the path with no size bound.

Someone who can rename entries in that directory can swap the file between steps 2 and 3 (TOCTOU). The process then reads bytes that were never checked. A file that grows after the `stat` is also read without a bound.

### TARGET 641fd49 (`apps/relayer/src/secrets.ts`)

Everything happens on one descriptor:
- `:50-51`: `openSync(path, O_RDONLY | O_NOFOLLOW | O_NONBLOCK)` on non-win32. A symlink is refused atomically, and a swapped-in FIFO cannot block.
- `:52`: `fstatSync(fd)` on that same fd.
- `:53`: `isFile()` and `size <= 4096`.
- `:54-56`: `mode & 0o077` must be 0.
- `:57-60`: owner is the service uid or root.
- `:62-69`: bounded `readSync(fd)` into a 4097-byte buffer. A read over 4096 bytes is refused, which covers growth after `fstat`.
- `:74-76`: `closeSync(fd)` in `finally`.
- Errors name the env var only: `:43,53,55,59,73,79,83,87`.

### Callers and other file reads

- `apps/relayer/src/main.ts:11-13` loads `RELAYER_KEY_FILE`, `QUOTE_SECRET_FILE` and `QUOTE_SECRET_PREVIOUS_FILE` only through `loadSecret` or `loadOptionalSecret`.
- `grep -rnE "readFileSync|openSync|fstatSync|O_NOFOLLOW|lstatSync|statSync" apps/relayer/src packages/relayer-guard/src` (non-test files) finds, besides `secrets.ts`, only `config.ts:468,481`. Those read the JSON config and the deployment manifests, which are not secrets, and are unchanged from #40.
- `packages/relayer-guard/src` reads no files.

**Conclusion:** TARGET's `secrets.ts` is byte-identical to #40's fixed version, so TARGET is exactly as strict.
