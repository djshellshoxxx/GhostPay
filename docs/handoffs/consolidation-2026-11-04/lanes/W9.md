# W9: EVM-3, unknown broadcast outcome must not release budget or nonce (W4 card 1)

Branch `claude/cw-w9` cut from origin/claude/consolidation-2026-11-04 @ 513b06a. Commit 8303c8c, pushed to origin/claude/cw-w9.

## Premise check: OPEN (confirmed)
- service.ts:730-748 on 513b06a: one `try` covered `nonces.acquire()` and `client.sendSweep()`. On any throw the `catch {}`
  called `nonces.invalidate()`, `budget.release(reserved)` and `loss.release()`, then returned `send_failed` 503. The error was not looked at.
- chain.ts:177-189: `sendSweep` = viem `wallet.writeContract`. Nothing told pre-broadcast and outcome-unknown errors apart.
  viem sends `eth_sendRawTransaction` with `retryCount: 0` (one attempt). Its `getNodeError` maps "already known" and
  "transaction already imported" to `NonceTooLowError`, so a classifier built on viem's node error types would wrongly
  treat a tx that is already in the pool as refused. My classifier uses its own list instead.
- Definitely pre-broadcast (safe to release): nonce read failure; deadline_too_soon after the nonce read; calldata
  encoding; the `eth_chainId` check and signing in `signTransaction`; a JSON-RPC error answer (RpcRequestError, or an
  RpcError other than UnknownRpcError) whose message matches nonce too low/high, nonce max, insufficient funds,
  intrinsic gas, exceeds block gas limit, underpriced, base fee, tx type, execution reverted, and that does not match
  already known/imported/exists.
- Outcome-unknown: TimeoutError, HttpRequestError (gateway page, socket reset), UnknownRpcError, -32603 internal error,
  "already known", any other error from any client (fail closed).

## Fix
- errors.ts: `SendRefused`, `SendOutcomeUnknown(txHash?)`.
- chain.ts: `sendSweep` now encodes, calls `wallet.signTransaction` (legacy, same nonce/gas/gasPrice), takes
  `keccak256(raw)`, then calls `wallet.sendRawTransaction`. Classifies errors as above. The returned hash is still the
  node's, as chain.test.ts expects.
- service.ts: the catch releases only for preHandoffRefusal, a failed nonce read, or `SendRefused`. Any other error
  records `rt.unknownSend` (with the reservations kept), logs warn `send_outcome_unknown` and increments
  `relayer_send_outcome_unknown_total`; the reply is still `send_failed` 503 and the breaker sees `send_failed`.
  `reconcileUnknownSend` runs in-lane after `reconcilePending` at the start of each job:
  receipt for the hash -> settleReceipt (nonce stays blocked until the pending count passes it); pending count > nonce ->
  broadcast confirmed, lane free, an unmined hashed send joins `rt.pending` (L5-06), an unhashed one keeps reservations
  until they lapse; pending count <= nonce and age >= `queue.receiptTimeoutSeconds` -> `send_not_broadcast`, release
  everything, nonce free. RPC errors leave it unsettled. While unsettled, jobs are refused with `send_unsettled` 503 +
  Retry-After before any simulation or reservation (breaker outcome neutral, no owner strike).
- harness.testutil.ts: `sendFails` now throws `SendRefused` (a node refusal, which is what the existing tests mean);
  a new `sendUnknown: { accepted, withHash? }` mode.
- api.test.ts: new describe block "unknown broadcast outcome (EVM-3)" (5 service tests + 10 viem-client classification
  tests over a custom transport and a local HTTP JSON-RPC server). The import list was extended for it; no existing test
  was changed.
- docs/specs/07: added section 5, a state note.
