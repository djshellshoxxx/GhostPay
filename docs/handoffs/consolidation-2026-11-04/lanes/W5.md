## Method

Pattern copied from BackupPanel.tsx: `useI18nOptional()` with `SOURCE_TRANSLATOR` fallback, so every existing English test (no provider) renders the same text. Async paths (camera status, scan notes, archive messages) read `t` through a ref so a result that settles after a language change uses the current language.

Classification (securityKeys.ts): new group `sharedComponentsAndChainViews` holds 152 security keys; 65 neutral keys were appended to `NEUTRAL_KEY_LIST`. Rule applied: consent, camera outcomes, warnings, key/secret/clipboard handling, destructive actions and their confirmations, address/fee/amount/total display, import/export outcomes, risk disclosures are SECURITY. Only plain control labels, headings and field labels are NEUTRAL. When unsure: SECURITY. Existing tests (`securityKeys.test.ts` exhaustive check) pass with every key in exactly one list.

Reused existing keys where the English text was already identical (same classification): `btc.warning.title`, `btc.section.*`, `btc.network.label`, `btc.wallet.{create,importLabel,importHint,import,copyAddress}`, `btc.appLocked`, `btc.lock`, `btc.payment.heading`, `btc.scan.{action,scanning,cancel,sweep,sweepAria,block}`, `btc.sweep.{destinationLabel,importQr,review}`, `btc.review.{heading,network,totalIn,fee,receives,change,approve,sign}`, `btc.signed.{heading,notSent,copyRaw}`, `btc.broadcast.{title,accepted}`, `btc.seed.*` (Solana backup), `pay.{destination,sellerFingerprint,lineItems,col.*}`, `sweep.oneTimeAddress`, `policy.account.balance`, `sellerKeys.{cancel,decrypting,passphrasesDiffer}`, `about.learns`.

es/ja/ar drafted with the existing terms (es cartera/barrido/analizar, ja ウォレット/スイープ/スキャン, ar محفظة/تحويل الرصيد/المسح). All three stay `machine-drafted: needs native review`; `REVIEWED_LOCALES` untouched; nothing marked reviewed.

## Decisions to review

1. Address and fingerprint direction: Mono is a plain `<code>`; Common.tsx is not mine, so `dir="ltr"` is set on the owned wrappers (camera paste textarea, payment-request URI and recipient input, proof JSON textarea, bill reference and fingerprint `dd`, view meta-address, stealth address, review addresses, RichText mono tag via `<bdi dir="ltr">`). Suggest adding `dir="ltr"` to `Mono` itself later (one line, covers every view).
2. Seller-facing quoted `Scan` references inside sentences (sol.instr.4 etc.) are translated as 「スキャン」/«Analizar»/«المسح» to match the button label of btc.scan.action.
3. New file `RichText.tsx`: `Trans` requires a provider and throws without one (existing component tests render without). RichText is the same renderer with a SOURCE_TRANSLATOR fallback. Used for sentences that embed `<Mono>` or `<strong>` (fee disclosure, router/relayer line, memo instructions). Not in the lane's file list; delete or relocate if you object.
4. `tagArchive.missing.unsupportedOne/Many` replaces an English `that chain/those chains` switch: two keys instead of ICU plural, because ar would need six plural forms for a security-text pair that stays English anyway. The chain list now uses `Intl.ListFormat` via the translator: 2 items read the same ("A and B"); 3 or more gain the Oxford comma in English ("A, B, and C"). No test or doc depends on 3+.
5. `Disclosure.tsx` still exports `OBSERVERS` and `LIMITS` (About.test and Home/About use them). Table rows now read catalog keys by index (`observerKey`, `limitKey`); `SharedComponents.i18n.test.tsx` fails if the English constant and the catalog text drift apart. New hook `useLimits()` returns the catalog text for `LIMITS`.
