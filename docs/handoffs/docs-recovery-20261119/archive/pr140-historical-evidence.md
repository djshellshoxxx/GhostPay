## Build and test

Requirements: Node >= 22 (`engines` in `package.json`; CI uses 22), Foundry 1.8.5 for the contracts.

```bash
npm ci --ignore-scripts      # install exactly what package-lock.json says, run no install scripts (the CI form)
npm run build:libs           # REQUIRED before typecheck/test/build: workspaces resolve each other through dist/
npm run typecheck
npm run lint
npm test                     # vitest with coverage thresholds in every workspace that has a test script
npm run build --workspace @ghostpay/web    # also runs the bundle scan (scripts/scan-bundle.mjs)
npm run test:e2e --workspace @ghostpay/web # Playwright; needs a Chromium build (not run by `npm test`)
npm run ci:scan-secrets      # scripts/scan-secrets.sh
npm run ci:check-actions     # scripts/check-actions-pinned.sh
npm run release:build        # scripts/release-build.sh
npm run release:repro        # scripts/repro-check.sh
```

CI ([`.github/workflows/ci.yml`](https://github.com/djshellshoxxx/GhostPay/blob/c5efadab9d9af6a0053f489ebe6c0c06e760d025/.github/workflows/ci.yml)) runs these jobs; docs-only pull requests (only `docs/` or `*.md` changed) skip the heavy ones:

- `ts-typecheck` (`npm run typecheck`), `ts-lint` (`npm run lint`) and `ts-check` (`npm run build`, the build-profile and example guard tests, `node scripts/i18n/check.mjs`, `npm audit --omit=dev --audit-level=high`) run in parallel.
- `ts-test` (matrix `core-crypto`, `btc-silent-payments`, `web`, `rest`): `npm test` per workspace; `rest` is every other workspace except `apps/relayer`.
- `ts-test-relayer`: `forge build` in `packages/contracts`, then `npm test -w apps/relayer` with `REQUIRE_ANVIL=1` (anvil e2e).
- `e2e`: `npx playwright install --with-deps chromium`, then `npm run test:e2e --workspace @ghostpay/web`.
- `contracts-test` (`forge build --sizes`, `forge test`), `contracts-coverage` (`forge coverage --ir-minimum --report summary --report lcov --report-file lcov.info`), `contracts-static` (`forge fmt --check`, `bash scripts/check-natspec.sh`, `forge snapshot --check`), `contracts-slither` (slither 0.11.6, solc 0.8.28, `--fail-medium`).
- `secrets-and-egress`: `scripts/scan-secrets.sh`, `scripts/check-actions-pinned.sh`, `scripts/check-tx-origin.sh`.
- Required-check gates: `typescript` (needs `ts-typecheck`, `ts-lint`, `ts-check`, `ts-test`, `ts-test-relayer`) and `contracts` (needs the four contracts jobs). `e2e` is not part of either gate.

## Kinds

| Kind | Colour | Border | Icon | Label | Examples | Handling |
|---|---|---|---|---|---|---|
| `secret` | red | thick solid | lock | SECRET | keystore backup, recovery data, anything that spends or decrypts | hidden until "Reveal"; auto-hides after 60 s and when the page is hidden; no copy, no download; warning text; not printed |

## Localization and approval-text integrity

The static Pages UI selects locale preference through `apps/web/src/i18n/context.tsx`, `storage.ts` and `languages.ts`. The default `catalog.ts` loader imports translation JSON as **same-origin, on-demand build chunks**, with bundled English available on first render and when a catalog fails to load. The provider ignores late results from a superseded locale request and does not make local-storage availability a condition for the user's in-session choice. These behaviors are covered in part by `apps/web/src/i18n/context.test.tsx` (RTL document attributes, failed loads, rejected storage, invalid choices and missing-provider handling); a separate rapid-switch/out-of-order completion regression is **not documented as tested** here.

**Security boundary:** `apps/web/src/i18n/translator.ts` uses the reviewed-locale registry in `apps/web/src/i18n/languages.ts` for sensitive review/approval wording. At the source-pinned #178 candidate, `REVIEWED_LOCALES` is empty: non-English catalogs remain machine-drafted and are **not approved translations for security-sensitive text**. The bundled English source is the final fallback for those keys, regardless of user-selected display language. Neutral labels can use draft catalogs. Updating a catalog's metadata alone must never grant review status; follow the repository i18n check and native-speaker review process before changing the registry. See `apps/web/src/i18n/translator.test.ts`, `context.test.tsx` and `scripts/i18n/check.mjs` for existing checks; this paragraph records source behavior, not a native-language, accessibility or security certification.
