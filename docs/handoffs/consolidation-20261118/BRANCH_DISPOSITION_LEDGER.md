## Method

GhostPay branch disposition census, 2026-11-18 (read-only).

Run: python3 -I census_20261118.py

Reads the GhostPay object database with read-only git commands only. The single command
that would write objects (`git merge-tree --write-tree`, used for conflict rehearsal) runs
with GIT_OBJECT_DIRECTORY pointed at a scratch directory and the repository object store as
an alternate, so no object, ref, index or worktree in the clone is modified.
GitHub is read with GET requests (`gh api`) only.

Method notes
- Unique non-merge patches: `git log --left-right --cherry-pick --no-merges REF...HEAD`, right
  side ('>') only. git 2.43 `--right-only` without `--left-right`/limiting lists left-side
  commits for histories with no merge base (gh-pages), so the '>' marker is parsed instead.
- Unique merges: `git rev-list --left-right --merges REF...HEAD`, right side only.
- Cross-check: `git cherry REF HEAD` '+' count (git cherry ignores merges) must equal the
  unique non-merge patch count for every ref with a merge base.
- 2026-11-17 class rule (reproduced): reference if HEAD==REF; ancestor if ahead==0;
  patch_equivalent if no unique non-merge patch (merges ignored); else requires_disposition.
  The strict 2026-11-18 rule additionally requires zero unique merge commits.

Additional per-ref evidence in the JSON: merge bases with both references, unique patch lists and their paths, paths whose content still differs from the reference, a three-way blob check (branch / unified / candidate) on unique-vs-unified paths, a heuristic added-line retention check against the candidate, and for refs to integrate or port, a `git merge-tree` rehearsal and the GitHub check-run conclusions at the head (read with GET requests).

## Limits

- Ancestry and patch equivalence show historical incorporation, not current behavior or feature acceptance.
- Unique patch counts overlap across stacked branches and must not be summed.
