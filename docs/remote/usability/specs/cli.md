# Spec: command line (@ghostpay/cli, bin `ghostpay`)
## Requirements
- R1 Pure entry `run(argv, io): Promise<number>`. All effects (stdout, stderr, files, stdin, env, clock, randomness, node version) are injected via `Io`; `bin.ts` is the only file that touches `process`/`fs`.
- R2 Offline: no network, no telemetry, no update check, no third-party calls. `doctor` states this and performs no I/O beyond local self-tests.
- R3 Secrets: signing keys and webhook secrets are read only from a file (`--key-file`, `--secret-file`), stdin (`--key-stdin`, `--secret-stdin`) or a named environment variable (`--key-env NAME`, `--secret-env NAME`). `--key`, `--secret` and similar value flags are refused with guidance and the value is never echoed. Secrets never appear in stdout, stderr, `--json`, or error text. Key bytes are zeroed after use. Only one input may use stdin.
- R4 Exit codes: 0 ok, 1 verification/validation failure (bad signature, expired, bad CSV, failed catalog check), 2 usage error, 3 I/O error (missing file, exists without `--force`, oversize input).
- R5 `--json` (anywhere): exactly one JSON object on stdout for results (`ok` field); errors as `{"ok":false,"error":{code,message,hint}}` on stderr. No ANSI, no colour.
- R6 Errors name the problem and a next step (`hint`), never echo untrusted input or secrets, and suggest the closest command/option for typos.
- R7 Inputs: files/stdin capped at 1 MiB; JSON parsed with the strict parser (no duplicate keys, integers only); money is bigint/decimal strings, never floats; unknown options rejected.
- R8 Outputs written with `--out` refuse to overwrite unless `--force`; node adapter writes mode 0600.
- Commands: `invoice create|sign|verify|link`, `webhook sign|verify`, `sub schedule`, `split compute`, `batch preview|confirm`, `export`, `sandbox chain demo`, `i18n check`, `doctor`, `help`, `--version`.
- C1 `invoice create --in spec.json [key opts] [--out f]`: NewInvoice JSON -> Invoice (fresh nonce from injected RNG). With a key, `signer` is derived (mismatch with a given `signer` fails) and a signed invoice is produced.
- C2 `invoice sign --in f [key opts]`: Invoice or SignedInvoice -> SignedInvoice.
- C3 `invoice verify --in f|-  [--pin hex66]...`: input is signed JSON or a `#gpi=v1.` fragment / payment URL. Reports `signatureValid`, `trust` (`invalid-signature|valid-signature|trusted-seller`), expiry from injected clock. Exit 1 on bad signature or expiry. Never prints line items or memo. Output states a valid signature is integrity only unless the signer is pinned.
- C4 `invoice link --in f --base URL [--encrypt]`: https base (localhost http only with `--allow-insecure-localhost`); output re-validated with `assertPaymentLink`; stderr warns the link is a bearer secret.
- C5 `webhook sign --body-file f|- secret opts [--nonce hex]` -> `GhostPay-Signature` value (body bytes exact, no trimming). `webhook verify --body-file f --header v|--header-file f secret opts [--tolerance s]`; exit 1 with reason `malformed|stale|bad-signature|replay`. Stateless: output says replay protection needs the receiver's nonce store. Secret = hex, >= 32 bytes.
- C6 `sub schedule --anchor T --cadence monthly:N|weekly:N|custom:SECONDS [--from i] [--count n]`: lists periods (unix + ISO UTC). T = unix seconds, `now`, or `YYYY-MM-DDTHH:MM:SSZ`.
- C7 `split compute (--total BASE | --amount DEC --decimals N) --share id=bps ...`: exact `splitByBps`; sums to total.
- C8 `batch preview --csv f --chain-id n --asset native|0x.. --decimals n --min D --per-recipient-max D --max-recipients n --max-total D [--duplicates reject|merge] [--allow-lowercase]` shows every row and a preview hash; `batch confirm ... --hash H` re-runs preview and `confirmBatch`; any change to file/options changes the hash and fails. Creates no payment.
- C9 `export --in invoices.json [--format csv|json|xero|iif] [--rounding m] [--out f]`: array of ExportInvoice or `{invoice, customer?, status?, paidMinor?}` wrappers.
- C10 `sandbox chain demo [--seed s]`: deterministic MockChain walkthrough (faucet, transfer, forced failure), carries the TEST banner.
- C11 `i18n check [--base en] [--catalog locale=file.json]...`: completeness of bundled or given catalogs; exit 1 on problems.
- C12 `doctor`: node >= 20, WebCrypto, randomness, secp256k1 sign/verify, encrypted-fragment round trip, bundled catalogs, clock sanity.
## Acceptance tests
Exit codes for each class; `--key 00..` refused and value absent from all output; key via file/env/stdin all produce same signature; wrong-length/non-hex key; two stdin consumers refused; env var unset; sign->verify->link->verify round trip (plain and encrypted); tampered amount fails verify (exit 1); expired invoice exit 1 with injected clock; pinned vs unpinned trust; webhook sign then verify, tampered body, stale clock, short secret, bad header; schedule Jan 31 monthly clamps to Feb 28; split 10001 by 3333/3333/3334 sums exactly; batch preview/confirm round trip, tampered CSV fails confirm, formula label rejected, wrong checksum rejected; export CSV formula-safe; sandbox demo deterministic; i18n missing key detected; doctor all pass and failing when injected randomness is constant; `--json` shape; overwrite refusal; oversize input; unknown option/command suggestions; no output contains the secret.
