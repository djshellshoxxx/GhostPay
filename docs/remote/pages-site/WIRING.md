# Wiring the Help link into the app

Status: the published Pages build already shows a static link strip (Help, How it works, Privacy options, Why) above the app. `build-site.sh` inserts it into the OUTPUT `index.html` only, before `<div id="root">`, plus `<link rel="stylesheet" href="./site.css">`. React only owns `#root`, so the strip survives. No scripts, CSP unchanged. `apps/web` is not modified.

That patch exists only for Pages. For the real app (swarm 4, `apps/web`), a native link is cleaner:

1. In `App.tsx` header nav (`<ul className="nav">`), after the `ORDER` items add a list item with a plain anchor, not a `setView` button:
   `<li><a className="nav-btn" href="./help/">Help</a></li>`
   Use a relative href so it works under `/GhostPay/` and any other base. The Help pages are static files, so the app build must ship them (run `docs/remote/pages-site/build-site.sh`) or the link will 404.
2. In `views/Home.tsx`, next to "Read the full privacy notes and observer table", add `<a href="./help/observers.html">` and `<a href="./how-it-works.html">`.
3. CSP: `connect-src` does not matter for navigation; no change needed. Links are same-origin.
4. If the strip is kept in the Pages build and the in-app link is added, drop one of them to avoid two Help links.

Keep the status wording on the Privacy options page in step with the code: `src/pages/privacy-options.html` (cards are generated by hand from `docs/remote/privacy-specs/`; BUILT only for features present in `apps/web`).

## Layout of this directory
- `src/pages/**.html` page bodies (header comment sets title/description/prev/next); `src/diagrams.mjs` diagram content; `src/lib/diagram.mjs` tiny layout engine that emits inline SVG (viewBox only, `role=img`, `<title>`/`<desc>`, plus an auto-generated text version); `src/site.css`; `src/build.mjs`.
- `build-site.sh <out> [--skip-app]`: app build, theme, site, strip.
