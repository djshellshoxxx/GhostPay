## Method (what was actually run)

- Stryker 10.0.0 (`@stryker-mutator/core`, `vitest-runner`) + vitest 4.1.12 + typescript 5.9.3 installed in scratch only. Config (`stryker.base.mjs`): `coverageAnalysis: perTest`, `vitest.related: false`, `disableTypeChecks: true`, mutate `src/**/*.ts` minus tests, `*.testutil.ts`, `index.ts` (and `abi/`, `main.ts`). `ignoreStatic: true` for policy-scheme, chain-adapters, btc, apps/relayer (runtime too long otherwise); `inPlace: true` on the scratch copies of core-crypto, policy-scheme, chain-adapters, btc, apps/relayer because several tests read `../../test-vectors`, `../../contracts`, `../../../deployments` by relative path (sandbox mode moves `src` two levels deeper).
- The vitest-runner was patched in scratch (T2). Nothing in the repo or in the published packages was patched.
- Wall clock: secret-box 1.3 min, relayer-guard 4.3, core-crypto 17 (2 workers), policy-scheme 14, invoice-schema 32, chain-adapters ~80 (contended), btc 57, apps/relayer 49 (2 workers), on 4 cores shared with other agents.
- "Static survivors" (mutants in module-level / describe-time code) were re-checked by applying the mutant text to a fresh copy and running `vitest run --bail 1` (`verify_static.py`): core-crypto 0/30 killed, relayer-guard 0/13, policy-scheme 0/17, invoice-schema 0/45, btc 4/83, chain-adapters 56/126.
- Killers were validated two ways: they pass on the unmodified code, and `stryker run --mutate '<every previously surviving line>'` (`genmut.py`) was re-run with them present; the "+ killers" column counts mutants that changed from Survived/NoCoverage to Killed/Timeout in that re-run (dedup key: file, mutator, line, column, replacement; +-1 % rounding).
- Reproduce one package: `cd /tmp/claude-0/assure-stryker/ws/packages/<pkg> && ../../../node_modules/.bin/stryker run` (config `stryker.config.mjs` there; report `reports/mutation.json`, original run in `reports-before/`). Reproduce one survivor: `... stryker run --mutate 'src/ip.ts:96-96'` (copy the killer file into `src/` and it flips to Killed).

## Tooling findings (affect how much to trust any Stryker + Vitest run in this repo)

- T1 [high, process] `@stryker-mutator/vitest-runner@10.0.0` is incompatible with the repo's `vitest@5.0.5`: the dry run passes, but every mutant run executes **0 tests** (mutant runs reported `Ran 0.14 tests per mutant`, score 2.1 %, every mutant "Survived"). Evidence: first secret-box run, 230 of 235 survived. Repro: install `@stryker-mutator/vitest-runner@10.0.0` next to `vitest@5.0.5` and run Stryker in `packages/secret-box`. Fix/workaround: pin `vitest@4.1.x` for the mutation job (every suite I ran under Stryker passed on 4.1.12), or wait for a runner release that supports vitest 5. A CI mutation gate built on the current pair would silently pass.
- T2 [medium] Even on vitest 4 the runner ignores a test **file** that fails during collection (an exception thrown at `describe`/import time): it reports `Complete` with fewer tests, so mutants in code that runs at import time or describe time are reported as survivors although the suite fails. Evidence: `ip.ts:51-58` mutants in relayer-guard. Workaround used: in `vitest-test-runner.js` treat `file.result.state === 'fail'` as a failed test (`patch.py`). Without it relayer-guard scored 82.5 % (119 survivors) instead of 86.2 % (94): 25 false survivors.
- T3 [medium] With `ignoreStatic` / runtime activation, mutants of module-level initialisers (e.g. the `CHAINS` table, regex constants) can be reported Survived although the suite fails when they are applied (chain-adapters: 56 of 126). Use `verify_static.py` (apply by hand + `vitest --bail`) before believing a static survivor.
- T4 [low] Sandbox mode breaks tests that use `new URL('../../x', import.meta.url)`; use `inPlace` on a scratch copy.

## Security-relevant test gaps (surviving mutants that matter), most severe first

Severity = what an undetected regression in the covered code would allow. Every item has a killer test in this directory; "killed" means confirmed by the Stryker re-run. Repro for any item: `stryker run --mutate '<file>:<line>-<line>'` in the package copy, without the killer file.

1. **apps/relayer, hot-wallet and gas-budget controls are not asserted** [high]. `service.ts:335 breaker.trip()` removed survives (the request that sees the low balance still fails with `breaker_open`, but the breaker is not actually tripped, the next request with a recovered balance passes); `service.ts:360 budget.release(reserved)` and `:361 breaker.recordFailure()` on a failed broadcast; `:374` post-mined release arithmetic (`gasUsed * gasPrice` replaced by `/` still passes: the daily unreimbursed-gas budget would be refunded in full); `:312 price > maxGasPriceWei`, `:347 gasLimit > maxGasLimit`, `:334 balance < minBalanceWei` boundaries; `:198 fee < gasCost`; `:243 fee > cap`; `:246-247` deadline window; `:241 quote.expiresAt <= now`. Impact: relayer keeps sending from a drained hot key, or leaks gas without bound. Killers: `relayer-app.killers.test.ts`, blocks "relayer quote rules", "sweep validation boundaries", "hot-wallet safety", "HTTP front end", "config validation". The Stryker re-run kills `:335`, `:360`, `:361`, `:198`, `:241`, `:243`, `:246`, `:312`, `:334`, `:347`, `:374` (division variant) and the CORS/RPC-env/chain-id config checks (41 of 383 original survivors; the rest are strings, log fields, config numeric bounds and the equivalents below). Fix: keep them.
2. **btc-silent-payments `buildSpendTransaction` fee/dust guards** [medium; also covered by the differential campaign in `differential.md`, but not by unit tests]. Survivors: `FEE_TOO_HIGH` operands (`spend.ts:237`, both `fee*2 > total` and `fee > 10_000` sides and both `>`), burn-guard `fee > feeNoChange + dust` (`:234`), change threshold `candidate >= dust` (`:229`), `net <= 0`, `net < dust` (`:220-221`), payment `< dust` (`:224`), `total < paid + fee` (`:225`), fee-rate cap and vout/txid/duplicate input checks (`:176-187`), compact-size width switch in `estimateKeyPathVsize` (`:75`). Impact: silent over-payment of fees or sub-dust change. Fix: killers (exact-boundary spends with `estimateKeyPathVsize`).
3. **btc `spendPrivateKey` parity normalisation untested** [medium]. `receiver.ts:233 if (!hasEvenY(p)) d = N - d` negated, removed or always applied all survive: the doc contract "parity-normalized key" (`mulG(privateKey)` has even y) is never asserted; BIP-340 signing hides the difference. A consumer using the key outside Schnorr (PSBT tapscript tweaking, ECDSA) would get the wrong key. Killer: 48-tweak postcondition test (even-y public key, x equals `xOnlyPublicKey`). Killed.
4. **btc `inputs.ts` script classification accepts near-misses** [medium]. Every byte comparison of `isP2PKH/isP2SH/isP2WPKH/isP2TR` and the future-segwit window (`:30-61`) can be replaced by `true` without a test failing, as can annex handling and the NUMS exclusion (`:108-113`). BIP-352 input eligibility decides the shared secret: a sender and receiver that disagree on one input class lose the payment. Killer: one-byte-off table for each class. Killed, except length-prefix conjuncts that the following byte checks make redundant (`inputs.ts:34,40` partial-condition variants, `:98`, parts of `:112`).
5. **policy-scheme limit and delay boundaries** [medium]. `eip712.ts:230 amount > lp.limit` -> `>=` and `policy.ts:78 d > MAX_DELAY` -> `>=` survive (an order for exactly the limit, or a 30-day delay, would be refused or accepted wrongly); `router.ts:93` fee-recipient collision, `:98` non-bigint `minNet`, `:100` deadline-vs-now, `:106` permit+buffer exclusivity, `:116` 65-byte permit; `types.ts` typeof guards (array-wrapped hex reaches `.toLowerCase()` as a `TypeError`); `derive.ts:116` scanner address strictness (a mixed-case address with a bad EIP-55 checksum, which is legal on-chain data, must still match). Killed (except `derive.ts:117-118`, see "equivalent").
6. **chain-adapters oracle bounds and RPC hardening** [medium]. `quote.ts:85,95,99,100,103,104` (maxAge 1..604800, decimals 0..30, answer <= 2^255-1, roundId, skew, staleness) all flip without a failing test; `rpc.ts:86` lets `ftp://localhost`/`file://localhost` through when `allowInsecureLocalhost` is set; `:117/:222` response caps are not tested at the boundary; `:208` default timeout, `:217` request ids, `:235/:260` default params, `:238` `getBlock(..., false)`, `:282-284` retry policy, `:300` `error: null` handling (becomes a `TypeError` retried as a transport fault) and the default `sleep`/`random` (NoCoverage). `fetchTransport` (`:93-136`) was never exercised against a socket: headers, redirect:error, size cap, timeout. Killers use a loopback server. Killed.
7. **chain-adapters scanner arithmetic** [medium]. `logs.ts:207` the `[Announcement, schemeTopic]` filter sent to `eth_getLogs` can become `[]` unnoticed (a provider would then return every log of the announcer; correctness is saved only by later validation); reorg rollback `number - depth + 1` clamp (`:182`), head clamp (`:203`) and `doneThrough` (`:194`); `fees.ts:149 want > cap` (the `capped` flag), `:190/:193` flat-fee config anchors; `config/chains.ts` table (module-level; actually killed by `config.test.ts`, T3) but only half pinned (finality depths and block times are not asserted); `sweep.ts:268-278` permit name/version/nonce bounds. Killed. Not killed: `adapter.ts:208-229` (scan `toBlock` and abort handling), `router.ts:127,182,288-293`, `deployments.ts` policy-field regexes (see "remaining").
8. **invoice-schema: no negative tests for garbage around well-formed values** [medium]. Removing `^` or `$` from `ADDRESS_RE`, `META_RE`, `NONCE_RE`, `QTY_RE`, `TOKEN_AMOUNT_RE`, `SOURCE_RE`, `DEC_RE` and the envelope `KEY_RE/NONCE_RE/HEX_SIG_RE` survived: no test passed `zz<value>` or `<value>zz`. With the `$`/`^` gone `tokenAmount: "5x"` reaches `BigInt()` and throws a `SyntaxError` instead of a `SchemaError`, and `token`/`metaAddress` could carry attacker-chosen prefixes into signed bytes. Also: `ignoreBOM: true -> false` (`envelope.ts:285`: a BOM-prefixed private plaintext would be accepted after decryption), `decodeBase64Url` accepting code point 128 (`base64url.ts:61`), encoded-size check ordering (`envelope.ts:30,232`: a 30 000-char non-base64 string must fail as too large before decoding), JSON separators and whitespace set, `obj()` key-set check (`.every` -> `.some`), `pub`/`chainId` shape, surrogate-pair edges. Killed (61 of 132).
9. **relayer-guard trusted-proxy math** [medium]. `ip.ts:96` family guard removal survives: an operator trusting `::/0` would also trust every IPv4 peer (a v6 block's masked v4 bytes are all zero); `ip.ts:56` partial `::ffff:0:0/96` match (`::ff00:7f00:1` must not normalise to 127.0.0.1); `:130-131` bucket prefix bounds; `client.ts:60` `maxEntries` bounds; limiter refill/retry formulas (`limiter.ts:145,151`), `LossBudget` window index, global reset and strict global limit (`:207,208,241`), breaker window slide, failure-only trip, late-probe settle after timeout (`breaker.ts:177`), `openedAt` arithmetic. Killed (39 of 95 plus the equivalents below).
10. **secret-box** [low]. `dispose()` zeroisation never asserted (`secretBox.ts:219`); `useAsync` hands out the live buffer instead of a copy (`:179`); `scope.box()` on a closed scope does not dispose the fresh copy (`scope.ts:42`); `random()` length bounds; `assertNoSecretBox` depth/size limits and the Map/Set/null paths. Killed (19 of 37).
11. **core-crypto** [low]. `randomScalar` accepts scalar 1 (`rng.ts:38`), exactly 64 attempts (`:35`), buffer wipe in `finally` (`:41-42`), missing `getRandomValues` -> `RNG_UNAVAILABLE` (`:13`); `buildNativeMetadata` view tag 255 (`metadata.ts:29`); `strictHexToBytes` anchoring. Killed (8 of 52).
12. **btc blindbit / scanner** [low]. `blindbit.ts:100` user-only and password-only URLs, `:103` trailing-slash strip; `scanner.ts:47-74` empty-range arithmetic, pre-aborted signal, abort between tweaks, height mismatch -> `REORG_DETECTED`, metadata omission. Killed.

### Behaviour observations found while writing killers (not mutation results)

- O1 [low] `router.ts:204` `parsePermitSignature`: a permit signature whose v byte is outside {0, 1, 27, 28} (e.g. `0x...1d`) makes viem's `parseSignature` throw a bare `Error`, not a `ChainAdapterError`; callers that switch on `ChainAdapterError` will treat it as an internal error. Repro: killer `buffer bounds ... permit v`. Fix: wrap in try/catch -> `fail('INVALID_INPUT', ...)`.
- O2 [low] `apps/relayer/src/config.ts:123` documents "no wildcards" but `new URL('https://*.example').origin === 'https://*.example'`, so such an entry passes `parseOrigins`; harmless for exact-match CORS, misleading as validation. Fix: reject entries containing `*`.
- O3 [info] `secret.ts:28` (`Symbol.species` -> `Uint8Array`): `secret.slice()` / `subarray()` of a `SecretScalar` return plain, non-redacting `Uint8Array`s. The killer pins this; if it is not intended, drop the species override.
- O4 [info] `buildSpendTransaction` (btc) throws `INSUFFICIENT_FUNDS` when change would be sub-dust but the leftover exceeds `feeNoChange + dust`, even if a change address was given (by design, `spend.ts:234`); the killer documents it.

## Remaining survivors (after killers): classification

- Error/message strings (`StringLiteral` on `fail('CODE', 'text')`, `this.name = '...'`): 655 of the 1695 original survivors (39 %; 12 % in btc, 66 % in policy-scheme). Low value; kill only where a client matches on the text.
- Equivalent or defence-in-depth, cannot be killed black-box: redundant second validation (`PUBKEY_RE` anchors in invoice-schema because `validPoint` follows; `SIG_RE` because `hexToBytes` follows; secret.ts/ecc.ts `parseCompressedPoint` length/prefix checks because `Point.fromBytes` rejects the same inputs; decoded-size check in `parseFragment` because the encoded-size bound is stricter; `policy-scheme/limits.ts:114` sort comparator variants because equal leaves cannot occur; `grossForNet` initial estimate because two correction loops follow, and its `g += 1n` loop is dead); `min/max`, `<=`/`<` and xor length variants in `SecretBox.equals`; unreachable `ZERO_HASH`/`INFINITY_POINT`/`h === 0n`/`q.is0()` branches and `destination === account` (needs a hash fixed point); bip32 `il` range checks (need crafted vectors); `Array.isArray`/`typeof` guards whose coercion fails later with the same path.
- Zeroisation calls (`zeroize(x)`, `wipe`, `key.fill(0)`): 28 survivors on the call line itself (btc 17, core-crypto 6, policy-scheme 3, invoice-schema 1, secret-box 1) plus the `finally {` block mutants around them. Not observable without module-level spies on the secret module; no killer written. Suggested fix: `vi.mock` the zeroize helper in one hygiene test per package, or accept as unverifiable (ADR already says "best effort").
- Real gaps with no killer written (listed so they are not lost): `adapter.ts` (chain-adapters) scan `toBlock`/abort handling and `build()` option pass-through (lines 196-229); `router.ts:288-293` decode-side gross/value bounds; `deployments.ts:104-105,117,134` policy/signature handling; `btc/adapter.ts:43,81` vout/amount bounds and label/message omission; `btc/receiver.ts:145,168` multi-output `consumed` handling; `btc/tx.ts:81-94` varint micro-boundaries (partly killed); `apps/relayer` `server.ts:156-215` (headersSent, 500-path body, request-id echo), `limiter.ts:118-133` salt rotation and retry-after math, `budget.ts:14,44,56` day rollover, `log.ts:45-52` field allowlist conditions, `quoteToken.ts:22-27` address lower-casing (equivalent under `toUpperCase` only if both sides use it), `secrets.ts:40-67` file-mode/size/hex rules, `config.ts` numeric bounds.

## Not run / limits

- Mutation testing of Solidity (`packages/contracts`) and of `apps/web`: out of scope (TS libraries and the relayer only).
- Excluded tests (instrumented runs too slow or need anvil): `core-crypto/src/differential.test.ts` (500 random key sets vs scopelift SDK), `policy-scheme/src/anvil.test.ts`, `apps/relayer/src/e2e.anvil.test.ts`. Their exclusion lowers the reported scores; I did not run them under mutation.
- 259 static mutants were ignored by `ignoreStatic` (policy-scheme 53, chain-adapters 62, btc 60, apps/relayer 84). Static survivors in the same packages were re-checked by hand; static mutants that Stryker ignored were not.
- Stryker ran with `disableTypeChecks`, so mutants a type checker would reject count as ordinary mutants.
- The two 10 000-sat fee-boundary assertions in `btc-silent-payments.killers.test.ts` (tests `FEE_TOO_HIGH ...`, last two blocks) were added after the last Stryker re-run of btc; they pass on the unmodified code but their kill counts are not in the table.
- Percentages in the "+ killers" column use a dedup key and a subset re-run; expect +-1 %.
- No haiku sub-workers were used.
