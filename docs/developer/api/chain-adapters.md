# `@ghostpay/chain-adapters`

EVM adapter layer: turns a validated invoice into a checked router transaction, scans ERC-5564 announcements safely,
builds gasless-sweep and permit typed data, reads oracles, and talks to RPC fail-closed. Source:
`packages/chain-adapters/src/` (entry `index.ts` re-exports every module below). Depends on `@ghostpay/core-crypto`,
`@ghostpay/invoice-schema`, `viem` 2.57.7, noble. No key material is created or exported here.

| Module | Purpose |
|---|---|
| `config/chains.ts`, `config/tokens.ts` | chain table and verified-only token allowlist |
| `fees.ts` | `FEE_SCHEDULE`, router fee/net/gross maths, gas buffer, sponsor fee, flat-fee config |
| `deployments.ts` | strict deployment-manifest validator and loader |
| `router.ts` | `buildPaymentTx`, `decodePaymentCalldata`, `assertPreviewMatchesCalldata` |
| `sweep.ts` | EIP-712 `Sweep` and ERC-2612 `Permit` typed data, digests, noble signing |
| `rpc.ts` | verified JSON-RPC client, URL policy, retries, size cap, two-provider check |
| `logs.ts` | paginated, reorg-safe `Announcement` fetch with strict validation |
| `quote.ts` | Chainlink `latestRoundData` reader, heartbeat/sequencer guards, fiat-to-token conversion |
| `readback.ts` | `verifyManifest` / `assertManifestVerified`: compare a manifest with the chain (fail closed) |
| `verify.ts` | `verifyAnnouncementAmount`: `verified` vs `claimed` amounts of detected payments |
| `registry.ts` | ERC-6538 registry helpers (`buildRegisterKeys`, `lookupMeta`, `assertRegistryAvailable`, ...) |
| `adapter.ts` | `ChainAdapter` interface and `createEvmAdapter` |
| `abi/*.ts` | const-asserted ABIs; all but `erc6538.ts` are generated by `scripts/gen-abi.sh` (do not edit by hand) |

Shared types (`types.ts`): `Hex`, `Address`, `ZERO_ADDRESS`, `MAX_UINT256`.

## Errors

`class ChainAdapterError extends Error { readonly code: AdapterErrorCode }`; `message` is `"<CODE>: <detail>"`.
Codes: `INVALID_INPUT`, `INVALID_MANIFEST`, `CHAIN_DISABLED`, `CHAIN_MISMATCH`, `PREVIEW_MISMATCH`, `UNSUPPORTED_TOKEN`,
`FEE_REJECTED`, `RPC_URL_REJECTED`, `RPC_FAILURE`, `RESPONSE_TOO_LARGE`, `INVALID_LOG`, `QUOTE_FAILED`,
`MANIFEST_READBACK_FAILED`, `REGISTRY_UNAVAILABLE`, `SIGNING_FAILED`.
Messages never contain secrets, RPC URLs with credentials, or raw chain payloads.

## Deployment manifest (`deployments.ts`)

```ts
interface DeploymentManifest {
  chainId: number; announcer: Address; router: Address; sweepRelayer: Address; feeRecipient: Address; feeBps: 25;
  deployTx: { router: Hex; sweepRelayer: Hex }; solcVersion: string; commit: string;
  bytecodeHashes: { router: Hex; sweepRelayer: Hex }; date: string; signature?: Hex;
  policy?: { implementation: Address; factory: Address; feeToken: Address; flatFee: bigint; feeRecipient: Address;
             deployTx: { implementation: Hex; factory: Hex }; bytecodeHashes: { implementation: Hex; factory: Hex } };
}
const MAX_MANIFEST_BYTES = 16 * 1024;
function validateManifest(value: unknown, expectedChainId: number): DeploymentManifest
function loadDeployment(text: string, expectedChainId: number): DeploymentManifest
```

Stricter than `deployments/schema.json`: unknown/missing keys, zero addresses, `feeBps != 25`, `chainId !=
expectedChainId` (`CHAIN_MISMATCH`), all-zero hashes, bad commit/solc/date, wrong EIP-55 checksum, collisions
(announcer/router/sweepRelayer must be distinct; `feeRecipient` must not equal the router or sweep relayer), policy
fields all-or-none with matching `deployTx`/`bytecodeHashes` entries. The `signature` field is parsed but **never
verified** (audit S3-01). In JSON the policy fields are flat: `policyImplementation`, `policyFactory`, `policyFeeToken`,
`policyFlatFee` (decimal string), `policyFeeRecipient`; the validated object nests them under `policy`.

## RPC (`rpc.ts`)

```ts
interface RpcClient {
  readonly chainId: number;
  request(method: string, params: readonly unknown[]): Promise<unknown>;
  blockNumber(): Promise<bigint>;
  getBlock(number: bigint): Promise<BlockRef | null>;          // { number, hash, parentHash }
  getLogs(filter: LogFilter): Promise<readonly RpcLog[]>;     // { address, topics, fromBlock, toBlock }
}
interface ClientOptions extends UrlOptions {
  transport?: RpcTransport; timeoutMs?: number /*10000*/; maxResponseBytes?: number /*2 MiB*/;
  retries?: number /*2, max 5*/; baseDelayMs?: number /*200*/; sleep?: (ms: number) => Promise<void>; random?: () => number;
}
interface UrlOptions { allowInsecureLocalhost?: boolean }
interface RpcTransport { send(url: string, body: string, init: { timeoutMs: number; maxBytes: number }): Promise<string> }
class RpcHttpError extends Error { status: number; get retryable(): boolean }   // 429 and 5xx

function validateRpcUrl(raw: string, opts?: UrlOptions): string
const fetchTransport: RpcTransport
function createClient(chain: ChainConfig, url: string, opts?: ClientOptions): Promise<RpcClient>
function parseQuantity(v: unknown): bigint
function toQuantity(n: bigint): string                  // canonical '0x' + lowercase hex, no leading zeros
function requestWithFallbackCheck(a: RpcClient, b: RpcClient, method: string, params: readonly unknown[],
                                  project?: (result: unknown) => unknown): Promise<unknown>
```

- `createClient` calls `eth_chainId` first and throws `CHAIN_MISMATCH` if the endpoint reports another chain. It rejects
  batch responses, id mismatches, non-canonical quantities and over-size bodies.
- URL policy: `https:` and `wss:` only; `http:`/`ws:` only for `localhost`, `127.0.0.1`, `[::1]` with
  `allowInsecureLocalhost: true`. Credentials (`user:pass@`), fragments and empty hosts are rejected and never echoed.
  The default `fetchTransport` is http(s) only (`wss:` needs a custom transport), uses `redirect: 'error'`, and enforces
  a streamed size cap and abort timeout.
- Retries use full-jitter exponential back-off on transport failures, HTTP 429/5xx and JSON-RPC `-32005`/`-32097`
  only; never on malformed responses.
- `requestWithFallbackCheck` compares two providers' results as canonical JSON (after the optional `project`
  function, applied to both; the unprojected primary result is returned). `verifyManifest` and
  `fetchAnnouncements({ secondary })` use it. The web app does not pass a second provider yet
  (`docs/operators/local-scanner-and-rpc.md`).

## Logs (`logs.ts`)

```ts
const ANNOUNCEMENT_TOPIC: Hex   // keccak256("Announcement(uint256,address,address,bytes,bytes)")
        // = 0x5f0eab8057630ba7676c49b4f21a0231414e79474595be8e4c432fbf6bf0f4e7
interface ScannedAnnouncement extends PublicAnnouncement {
  schemeId: bigint; stealthAddress: Address; caller: Address; blockNumber: bigint; blockHash: Hex; logIndex: number;
  transactionHash?: Hex;     // when the provider reported a well-formed one
  confirmations?: bigint;    // head - blockNumber + 1; set by fetchAnnouncements only
  id: string;                // `${blockHash}:${logIndex}`
}
interface ScanCursor { nextBlock: bigint; last?: { number: bigint; hash: Hex } }
interface FetchOptions { chain: ChainConfig; client: RpcClient; announcer: Address; cursor: ScanCursor;
                         schemeId?: bigint /*1n*/; maxRequests?: number /*50*/; maxLogs?: number /*10000*/; maxRange?: number;
                         minConfirmations?: number /*1; integer >= 1*/; secondary?: RpcClient }
interface FetchResult { announcements: readonly ScannedAnnouncement[]; cursor: ScanCursor; truncated: boolean;
                        reorg?: { rolledBackTo: bigint }; skipped: number; head: bigint; scanHead: bigint }

function validateAnnouncementLog(log: RpcLog, announcer: Address, schemeId: bigint, from: bigint, to: bigint): ScannedAnnouncement | undefined
function fetchAnnouncements(o: FetchOptions): Promise<FetchResult>
```

Two failure classes: **provider faults** (wrong emitter, wrong topic0 or scheme topic, `removed`, block outside the
requested range, bad position fields) throw `INVALID_LOG`; **attacker content** (not 4 topics, undecodable or
non-canonical ABI data, ephemeral key not a valid 33-byte compressed point, empty metadata) is skipped and counted in
`skipped`. On cursor/chain-hash mismatch the cursor rolls back by `chain.finalityDepth` and `reorg.rolledBackTo` tells
you which stored announcements to drop. A range error (`-32602`/`-32005`) halves the window down to one block.
`truncated: true` means a cap stopped the call; resume with the returned cursor. `minConfirmations` limits the scan to
`scanHead = head - minConfirmations + 1` (pass `chain.finalityDepth` to never see reorg-able matches). With
`secondary` set, every `eth_getLogs` window (compared on a normalised projection) and the closing block hash must agree
between both providers, otherwise `RPC_FAILURE: providers disagree`. The generator-style `scan` cannot retract earlier
yields: after a reorg drop stored matches with `blockNumber >= rolledBackTo`.

## Router builders (`router.ts`)

```ts
type RouterMethod = 'payERC20' | 'payERC20WithPermit' | 'payNative' | 'payERC20WithBuffer'
interface PaymentTx { to: Address; data: Hex; value: bigint }
interface PaymentPreview {
  method: RouterMethod; chainId: number; router: Address; token: Address | 'native'; stealth: Address;
  gross: bigint; fee: bigint; net: bigint; minNet: bigint; deadline: bigint;
  ephemeralPublicKey: Hex; metadata: Hex; value: bigint; maxBufferWei?: bigint; permit?: { v: number; r: Hex; s: Hex };
}
interface BuiltPayment { tx: PaymentTx; preview: PaymentPreview }
interface BuildPaymentInput {
  chain: ChainConfig; deployment: DeploymentManifest;
  invoice: Pick<Invoice, 'chainId' | 'token'>;
  payment: Pick<DerivedStealthPayment, 'stealthAddress' | 'ephemeralPublicKey' | 'viewTag'>;
  grossAmount: bigint; minNet?: bigint; deadline: bigint; now?: bigint;
  permitSignature?: Hex;                                         // 65-byte r||s||v
  buffer?: { bufferWei: bigint; maxBufferWei?: bigint };
  findTokenFn?: (chainId: number, address: string) => TokenConfig | undefined;   // tests / future chains
}
function buildPaymentTx(input: BuildPaymentInput): BuiltPayment
function decodePaymentCalldata(tx: PaymentTx, chainId: number): PaymentPreview
function assertPreviewMatchesCalldata(preview: PaymentPreview, tx: PaymentTx, expectedChainId: number): void
const ROUTER_NATIVE_MARKER: Address
```

Method selection: native invoice -> `payNative` (value = gross); ERC-20 + `permitSignature` -> `payERC20WithPermit`;
ERC-20 + `buffer` -> `payERC20WithBuffer` (value = `bufferWei`, cap `maxBufferWei` defaults to `bufferWei`); else
`payERC20`. Permit and buffer are mutually exclusive; both are invalid for native. The token must be on the allowlist
(`UNSUPPORTED_TOKEN`), and `permit` requires `TokenConfig.permit`. `decodePaymentCalldata` requires the re-encoded
calldata to equal the input byte for byte, checks metadata against the router layout and `net = gross - routerFee`, and
rejects `minNet > net`. `assertPreviewMatchesCalldata` compares method, chainId, router, token, stealth, gross, fee,
net, minNet, deadline, ephemeral key, metadata, value, `maxBufferWei` and permit `v/r/s`; any difference throws
`PREVIEW_MISMATCH: field <name>`. The mismatch of the **fee recipient** cannot be detected from calldata.

```ts
                         nonce(t: Address, owner: Address): Promise<bigint>; domainSeparator?(t: Address): Promise<Hex> }

```

`buildSweepTypedData` rejects, before anything is signed, every order the contract would revert on: zero addresses, any
address equal to the relayer, `amount <= fee`, and `destination == owner`, `feeTo == owner` or `feeTo == destination`
(the contract's balance-delta checks revert on those). `signSweep` requires `order.owner` to be the address of the key.
`buildPermitTypedData` fails closed on empty or oversized name/version and, when the reader supplies it, on a
`DOMAIN_SEPARATOR` different from the computed one (DAI-style and non-standard tokens). Circle USDC reports version `"2"`.

```ts
                                price: Pick<Price, 'answer' | 'decimals'>; tokenDecimals: number; side: RoundingSide }): bigint
```

`readPrice` refuses non-positive or oversized answers, `roundId == 0`, `answeredInRound < roundId`, `updatedAt == 0`,
stale or future-dated answers, decimals outside 0..30. `fiatToTokenAmount` is exact bigint math; `payer` rounds up, `seller`
rounds down; a currency mismatch between invoice and feed is refused. When `heartbeatSeconds` is given the accepted age is
capped at `heartbeat + margin` **regardless of the invoice-supplied `maxAgeSeconds`** (the invoice is seller-authored),
so callers should always pass it; `sequencerUptime` makes `readPrice` run `assertSequencerUp` first (Chainlink L2
feed: answer 0 = up, `startedAt` = last status change, fail closed during the grace period). `FeedConfig` gained optional
`heartbeatSeconds` and `sequencerUptimeFeed`. Because `FEEDS` is empty, `fiat_quote` invoices cannot be paid in practice.

## `ChainAdapter` (`adapter.ts`)

```ts

  readonly chainId: string;                                   // EVM numeric id as a string
  parseRecipient(input: string): RecipientAddress;

  scan(range: ScanRange, keys: ViewCapability, signal: AbortSignal): AsyncIterable<DetectedPayment>;
  readonly fees: FeeCapability;                               // { checkout, checkoutBps?, gasSponsorship, flatSecurity }, FeeStatus = 'enforced' | 'not_enforceable' | 'not_deployed'
}

                           router: Address; feeRecipient: Address; build(opts: BuildOptions): BuiltPayment }

                         buffer?: { bufferWei: bigint; maxBufferWei?: bigint }; rng?: RandomSource }

interface DetectedPayment { stealthAddress: Address; announcement: ScannedAnnouncement; metadata: ParsedMetadata | undefined; viaRouter: boolean;
                            verification: AmountVerification; confirmations: bigint; final: boolean }   // final = confirmations > chain.finalityDepth
interface RequestOptions { quotedTokenAmount?: bigint }

  chain: ChainConfig; deployment: DeploymentManifest; client: RpcClient;
  readback?: ReadbackResult;            // from verifyManifest; a failed result makes createEvmAdapter throw MANIFEST_READBACK_FAILED
  secondaryClient?: RpcClient;          // scan reads must agree across both providers

```

`createEvmAdapter` throws `CHAIN_DISABLED` unless the chain is enabled and `CHAIN_MISMATCH` unless chain, deployment and
client agree on `chainId`. If `deps.readback` is given it must be fully passing (`assertManifestVerified`); **omitting it
keeps the legacy behaviour of trusting the manifest as-is, so apps should always pass it** (see [Manifest
read-back](#manifest-read-back-readbackts)). Amount semantics for `buildPaymentRequest`: for `fixed_token`, `tokenAmount` is what the
**seller receives** when `feePolicy = 'payer_pays'` (gross = `grossForNet`, which may exceed the target by at most one
base unit) and the **gross** the payer spends when `'seller_pays'`; `fiat_quote` invoices need `quotedTokenAmount`
interpreted the same way. `scan` is an async generator over `fetchAnnouncements` + core-crypto `checkAnnouncement`.
`scan` also fills `verification` (see [Announcement amount verification](#announcement-amount-verification-verifyts)),
`confirmations` and `final`, and calls `deps.onReorg` when a pass detects a reorg. The adapter reports
`fees = { checkout: 'enforced', checkoutBps: 25, gasSponsorship: 'enforced', flatSecurity }` where `flatSecurity` is
`'not_deployed'` without `manifest.policy`, `'enforced'` with `policy.flatFee > 0n` and `'not_enforceable'` with a zero fee
(it does not prove the policy contracts are live; `verifyManifest` checks their code hashes).

## Manifest read-back (`readback.ts`)

```ts
type ReadbackCheckName = 'chainId' | 'router.FEE_RECIPIENT' | 'router.ANNOUNCER' | 'router.FEE_BPS' | 'router.codehash'
  | 'relayer.codehash' | 'announcer.code' | 'announcer.codehash' | 'policy.implementation.codehash' | 'policy.factory.codehash' | 'providers'
interface ReadbackCheck { name: ReadbackCheckName; expected: string; actual: string /* 'error' when the read failed */; pass: boolean }
interface ReadbackResult { ok: boolean; checks: readonly ReadbackCheck[] }
interface ReadbackOptions { requireTwoProviders?: boolean; expectedAnnouncerCodehash?: Hex }
function codehashOf(code: unknown): Hex                       // MANIFEST_READBACK_FAILED for empty code or an EIP-7702 designator (0xef0100...)
function verifyManifest(m: DeploymentManifest, clients: readonly RpcClient[], opts?: ReadbackOptions): Promise<ReadbackResult>
function assertManifestVerified(r: ReadbackResult): void      // throws MANIFEST_READBACK_FAILED naming the failed checks
```

`verifyManifest` never throws on a chain mismatch; a read that throws is a failed check. It compares `FEE_RECIPIENT()`,
`ANNOUNCER()`, `FEE_BPS()` (must be 25) read from the router, `keccak256(eth_getCode)` of the router, sweep relayer and
(if present) policy implementation/factory against `bytecodeHashes` (runtime, post-immutable hashes, as
`DEPLOYMENT_MANIFEST.md` defines them), and that the announcer has real code (optionally a pinned codehash). With two
clients every read must agree. **Nothing in this package forces an app to call it**: pass the result to `createEvmAdapter({ readback })`. The web app calls it from `useManifest` (via `Services.verifyManifest`, one user RPC, a failure becomes the `unverified` manifest state) and the relayer calls it once at startup (`buildChainClients`); neither threads `readback` into the adapter.
Not covered: the manifest `signature`, the sweep relayer's `DOMAIN_SEPARATOR()`, caching and periodic re-checks
(`DEVIATIONS.md` item 14). Tested against a mock RPC; no anvil test yet. Both consumers use one provider.

## Announcement amount verification (`verify.ts`)

```ts
const TRANSFER_TOPIC: Hex     // keccak256("Transfer(address,address,uint256)")
type ClaimedReason = 'no_metadata' | 'native_unverifiable' | 'token_not_allowlisted' | 'no_transfer_found' | 'verification_failed' | 'not_checked'
type AmountVerification =
  | { status: 'verified'; source: 'router' | 'transfer_logs'; token: Address; amount: bigint }
  | { status: 'claimed'; reason: ClaimedReason; claimed?: { token: Address; amount: bigint } }
interface VerifyAmountInput { client: Pick<RpcClient, 'getLogs' | 'chainId'> & Partial<Pick<RpcClient, 'request'>>;
                              announcement: ScannedAnnouncement; metadata: ParsedMetadata | undefined; viaRouter: boolean;
                              isAllowedToken?: (token: Address) => boolean;
                              secondaryClient?: Pick<RpcClient, 'request' | 'chainId'>;   // Transfer logs must match on both providers
                              consumedTransfers?: Set<string> }                           // shared `blockHash:logIndex` ledger
function verifyAnnouncementAmount(i: VerifyAmountInput): Promise<AmountVerification>   // never throws
```

Router announcements are `verified` (the router enforces metadata == transfer; this inherits the read-back trust).
Direct payments are `verified` only if allowlisted-token ERC-20 `Transfer(_, stealth)` logs exist in the announcement's
own block (and transaction when known); native-coin direct payments stay `claimed`. **Show an amount as received only when `status === 'verified'`.** With `secondaryClient`, the `Transfer` logs must be identical
on both providers or the verdict degrades to `claimed: verification_failed` (round-3 NC-01, fixed in `ab09bad`);
`consumedTransfers` makes a `Transfer` log verify at most one announcement (NC-02; `createEvmAdapter.scan` creates one set per
call, so the ledger is not persisted across calls, the first announcement in log order takes the transfer, and the verified
amount is the log value, not capped by the announced amount: `DEVIATIONS.md` item 19). `getLogsAgreed` (two-provider
`eth_getLogs` on a normalised projection) is exported from `logs.ts` for this purpose.

## Pitfalls

- `BuildOptions` has no `chainId`/router override: they come from the manifest. If your manifest is wrong, your payment
  is wrong. Display `req.feeRecipient` and `req.router` to the user, and run `verifyManifest` first: without it the
  manifest is trusted as given and its `signature` is never verified (audit S3-01).
- `now` is optional in `BuildOptions`; pass it so a past deadline is rejected before the wallet prompt. The on-chain
  check is inclusive (`block.timestamp <= deadline`) while the builder requires `deadline > now`.
- Each `req.build()` call derives new randomness. Cache the result if you need to show then send the same tx.
- `fetchAnnouncements` stops at `maxRequests` (50) or `maxLogs` (10 000) with `truncated: true`; loop until it is false.
- `viaRouter` and parsed metadata are labels, not authentication (audit L-02): verify the real balance delta.
- Packages `typecheck`/`test` resolve `@ghostpay/core-crypto` and `@ghostpay/invoice-schema` to their `src` through tsconfig
  `paths` and vitest `alias`; the built `dist` is what other workspaces and the web app consume.
