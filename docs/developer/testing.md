# Testing guide

Sources: each package's `vitest.config.ts` and `src/*.test.ts`, `packages/contracts/{foundry.toml,echidna.yaml,test/}`,
`.github/workflows/{ci,nightly,release}.yml`, `docs/remote/contracts-assurance.md`, `test-vectors/README.md`.
Test counts in READMEs are snapshots; re-run before relying on them. Coverage and test counts establish regression
safety, **not** correctness or security (every package README says so).

## 1. Layers and where they live

| Layer | TypeScript | Solidity |
|---|---|---|
| Unit | `src/*.test.ts` next to the code (vitest) | `test/<Contract>.t.sol` |
| Property / fuzz | `fast-check` in `properties.test.ts`, `fuzz.test.ts`, `fees.test.ts`, `sweep.test.ts`, `quote.test.ts`, `roundtrip.test.ts`, `keys.test.ts`, `units.test.ts`, `uri.test.ts`, `base64url.test.ts` | `test/*.fuzz.t.sol` (`testFuzz_*`, 10 000 runs by default) |
| Invariant | n/a | `test/*.invariant.t.sol` with handler contracts (256 runs x depth 50) |
| Property fuzzing (Echidna) | n/a | `test/echidna/Echidna{Router,Sweep,Policy}.sol` + `echidna.yaml` |
| Fixed vectors | `vectors.test.ts` against `test-vectors/*.json` and the BIP-352 JSON | n/a |
| Differential | `core-crypto/src/differential.test.ts` (1000 payments vs `@scopelift/stealth-address-sdk`), `policy-scheme` vs viem/core-crypto, btc vs `@scure/bip32` | n/a (the announcer is the CC0 reference source compiled locally) |
| Negative / hostile input | `negative.test.ts`, `hash-edge.test.ts`, `secrets.test.ts`, parser fuzz | malicious-token mocks in `test/mocks/`, `test/audit/*.sol` |
| Real-contract integration | `apps/relayer/src/e2e.anvil.test.ts`, `packages/policy-scheme/src/anvil.test.ts` (local anvil) | deploy-script tests `Deploy*.t.sol` |
| Component / UI | `apps/web/src/**/*.test.tsx` (vitest + jsdom + Testing Library) | n/a |
| End to end | `apps/web/e2e/*.spec.ts` (Playwright, Chromium only) | n/a |
| Static | ESLint (type-checked), `tsc --noEmit`, `scan-bundle.mjs`, `scan-secrets.sh` | `forge fmt --check`, forge lint (inline `forge-lint:` justifications), `check-natspec.sh`, Slither |

Naming and conventions you will meet:

- `*.testutil.ts` and `src/test/*` are test-only helpers excluded from coverage: `fixtures.testutil.ts`,
  `rng.testutil.ts` (`seededRng(seed)`: a deterministic sha256-counter `RandomSource` that records outputs),
  `rpc.testutil.ts`, `spend.testutil.ts`, `vectors.testutil.ts`.
- JSDoc `@testVector <id>` tags (e.g. `scheme1-001`, `invoice-v1-sample`, `policy-scheme.accounts`) name the vector set a
  function is pinned by.
- Every audit fix carries a regression test (`test_EXPLOIT_*` documents a residual weakness that is *accepted*; a fixed one
  was converted to a passing regression test). Do not "fix" an EXPLOIT test by weakening it; change the contract or the ADR.
- Production code never passes an RNG. Tests inject one through the optional `rng` parameter.

## 2. Running tests

```bash
npm run build:libs                       # first, always
npm test                                 # all workspaces, with coverage thresholds
npm test -w @ghostpay/core-crypto        # one workspace
cd packages/core-crypto && npx vitest run src/vectors.test.ts    # one file
```

Coverage thresholds (`vitest.config.ts`): statements/lines/functions 95, branches 90 for core-crypto, invoice-schema,
chain-adapters, policy-scheme (ABI files excluded), btc-silent-payments (`adapter-types.ts` excluded) and the relayer
(`main.ts` excluded); 90/85/90/90 for the web app (explicit exclusions in `apps/web/vite.config.ts`, justified in
`apps/web/DEVIATIONS.md`). `testTimeout` 60 s, `pool: 'forks'`. The core-crypto and policy-scheme configs inline
`@scopelift/stealth-address-sdk` because its ESM uses extensionless imports plain Node rejects.

Web component tests opt into jsdom per file with `// @vitest-environment jsdom`; the default environment is `node`.
Playwright is separate (`npm run test:e2e -w @ghostpay/web`, see [local-setup.md](local-setup.md#6-playwright-web-e2e)).

## 3. Vectors

| File | What | Generated by | Consumed by |
|---|---|---|---|
| `test-vectors/scheme1.json` | ERC-5564 scheme-1 vectors pinned by ADR-0001 (mid-range, smallest, largest, boundary, leading-zero and alternating-bit scalars), plus the two 57-byte metadata strings per vector | `node test-vectors/generate.mjs` using the ScopeLift SDK from fixed public test keys (loaded through Vite's SSR loader); never imports `@ghostpay/core-crypto` | `packages/core-crypto/src/vectors.test.ts` (byte equality) |
| `test-vectors/policy-scheme.json` | scheme `0x47500002`: deployment (chain 31337, factory/implementation as `CREATE(deployer, 1/0)`), type strings and typehashes, four limits trees with proofs, invalid trees with expected error codes, four accounts, signed `Withdraw`/`Cancel*`/`ProposeDestination` | `node test-vectors/generate-policy-scheme.mjs` (SDK + viem + an independent StandardMerkleTree re-implementation; never imports the package) | `policy-scheme/src/vectors.test.ts`, `anvil.test.ts` |
| `packages/btc-silent-payments/test-vectors/send_and_receive_test_vectors.json` and the BIP texts | official BIP-352 vectors (28 cases = 28 sending + 29 receiving), BIP-350 Bech32m vectors and BIP-32 vectors 1-4 parsed out of the saved BIP text | downloaded unmodified from `bitcoin/bips` on 2026-10-21; SHA-256 sums in the README there | `vectors.test.ts`, `bech32m.test.ts`, `bip32.test.ts`, `spend-vectors.test.ts` |

Rules: the keys inside vectors are public; never use them for anything but tests. A regeneration that changes anything
other than `generatedAt` means the reference output changed and must be investigated, **never fixed by editing expected
values**. The BTC test asserts exact counts (28/28/29) so a silently modified file fails. Crypto changes require updated
vectors and a differential test (`SECURITY.md`).

## 4. Foundry: unit, fuzz, invariant

Suites (`packages/contracts/test/`): `GhostPayRouter{,.fuzz,.invariant}.t.sol`, `GhostPaySweepRelayer{,.invariant}.t.sol`,
`PolicyAccount{,.fuzz,.invariant}.t.sol`, `PolicyAccountFactory.t.sol`, `GhostPayPolicyRouter{,.fuzz,.invariant}.t.sol`,
`Deploy.t.sol`, `DeployPolicy.t.sol`, `DeployPolicyRouter.t.sol`, `audit/{Router,Sweep,Policy}.audit.t.sol`. Base contracts:
`Base.t.sol`, `SweepBase.t.sol`, `PolicyBase.t.sol`, `PolicyRouterBase.t.sol`. Mock tokens (`test/mocks/`): standard
(`MockERC20`, configurable decimals; tests use 2, 6 and 18), `NoReturnToken`, `FalseReturnToken`, `FeeOnTransferToken`, `ReentrantToken`, `HookToken`,
`PermitToken`, `BlacklistToken`, plus `NativeReceivers.sol`; `test/utils/ERC5564Announcer.sol` is the CC0 reference
announcer compiled locally (the "fork-style" announcer test: no live fork is used).

Profiles (`foundry.toml`): default 10 000 fuzz runs, invariants 256 runs x depth 50, `fail_on_revert = false`; `dev` 256 / 64 x
50; nightly CI runs `forge test --fuzz-runs 100000`.

Invariants by suite (the `invariant_*` functions):

| Suite | Invariants |
|---|---|
| `GhostPayRouterInvariantTest` | `routerHoldsNothing`, `recipientsPlusFeeEqualGrosses`, `nativeAccounting`, `feeOnTransferNeverSucceeds` |
| `GhostPayPolicyRouterInvariantTest` | the same four plus `onlyPolicyAccountsReceive` |
| `GhostPaySweepRelayerInvariantTest` | `nonceSingleUse`, `relayerCannotAlterSignedTerms`, `balancesMatchSignedOrders` |
| `PolicyAccountInvariantTest` | `fundsOnlyLeaveToDestination`, `timelocksNeverShortened`, `executedIdSingleUse`, `noUnrecordedAllowance`, `windowCapRespected`, `foreignSignaturesNeverAccepted`, `policyImmutable` |

Handlers (`RouterHandler`, `SweepHandler`, `PolicyHandler`, `PolicyRouterHandler`) drive bounded random call sequences with
ghost accounting. When you add a state-changing function, extend the handler and add or adjust an invariant; a
unit test alone is not enough for this repository.

Adversarial PoCs: `test/audit/*.audit.t.sol` assert that audited weaknesses are real or fixed (return-data bomb, limit-leaf
swap, fee-recipient blacklist, hostile permit gas burn, stipend senders). A baseline run without them:
`forge test --no-match-path 'test/audit/*'`. The same findings have JavaScript PoCs in `docs/audits/poc/` (`run-all.sh`
needs built libs, a built web bundle and relayer, and a preinstalled Chromium).

## 5. Echidna

Harnesses: `test/echidna/EchidnaRouter.sol`, `EchidnaSweep.sol`, `EchidnaPolicy.sol`. Config `packages/contracts/echidna.yaml`
(property mode, `testLimit 300000`, `seqLen 20`, `shrinkLimit 2000`, 4 workers, `seed 20261021`, senders `0x10000/0x20000/0x30000`,
deployer `0x40000`, `balanceContract 1000 ether`). Run one harness at a time from `packages/contracts`:

```bash
echidna test/echidna/EchidnaRouter.sol --contract EchidnaRouter --config echidna.yaml --corpus-dir echidna-corpus-router --format text
```

It needs `crytic-compile` on `PATH` and a compiler Echidna can find (offline, the `solc` path in `foundry.toml`). Properties
are `echidna_*` view functions returning `true`:

| Harness | Properties |
|---|---|
| Router | `router_never_holds_tokens`, `fee_plus_net_eq_gross`, `native_fee_plus_net_eq_gross`, `fee_recipient_only_gets_bps` |
| Sweep | `sweep_nonce_single_use`, `used_nonces_marked`, `relayer_never_holds_tokens`, `token_conservation` |
| Policy | `funds_only_to_destination`, `destination_only_changes_via_timelock`, `timelocks_never_shortened`, `policy_immutable`, `rolling_window_cap` |

Each harness also has `echidna_canary_*` properties that are **expected to fail** (they prove the success paths are
reachable); a run therefore prints "failed" lines by design. Evidence level: `docs/remote/contracts-assurance.md` records one
run per harness of about 300 000 calls with no violation, recorded with the commit that added the harnesses (`3524033`). The harnesses were modified
again in the round-3 contract commit `50881e4` (salt-only policy router, factory fee waiver); this page does not know whether
the campaign was repeated, and it was not re-run for this page. (`packages/contracts/README.md` still says "Echidna was
not run"; that sentence predates the assurance document.) Echidna is **not in
CI** (the nightly header comment saying no harness exists is stale), there is no multi-seed or long campaign, no Slither
hints were used, the router harness has only four code-less stealth EOAs (hostile receivers and reentrant tokens are covered
by Foundry tests only), and `PolicyAccountFactory` is not fuzzed.

## 6. Anvil end-to-end tests

See [local-setup.md](local-setup.md#5-anvil-anvil_bin-require_anvil) for the environment. What they establish:

- `apps/relayer/src/e2e.anvil.test.ts`: deploys the compiled `GhostPaySweepRelayer` and `PermitToken`, starts the real relayer
  runtime against the local node, quotes and sweeps through it (throw-away keys, `anvil_setBalance`).
- `packages/policy-scheme/src/anvil.test.ts`: deploys `PolicyAccount`, `PolicyAccountFactory`, `GhostPayPolicyRouter`, the
  reference announcer and a mock token from the vector deployer key; checks predicted addresses, typehashes, domain
  separators, that the vector signatures are accepted on-chain, the withdraw/cancel/destination flows and a router
  payment -> scan -> deploy -> withdraw round trip.
- There is **no** anvil differential test of `routerFee` / `grossForNet` against the compiled `GhostPayRouter`; parity is
  shown by shared boundary vectors (399/400), a regex over the Solidity constants and the Foundry tests
  (`packages/chain-adapters/DEVIATIONS.md` item 13). There is no anvil test of `verifyManifest` (it is tested against a mock RPC).

## 7. Writing tests: checklist

1. Put the test next to the code; keep deterministic inputs (`seededRng`) unless you are deliberately fuzzing.
2. For parsers and decoders: add a hostile-input case (malformed, oversized, non-canonical, duplicate keys) and assert the
   typed error `code`, never the message text.
3. For anything cryptographic: add or extend a vector set and a differential check; do not derive expected values from the
   code under test.
4. For money maths: add boundary vectors (`0`, `1`, `399`, `400`, `MAX_ROUTER_GROSS`, `MAX_ROUTER_GROSS + 1`) and a property
   (fast-check) tying the TypeScript function to the Solidity formula.
5. For contracts: unit test every revert (use the error selector), a fuzz test for arithmetic, an invariant if the function
   moves value, a mock-token case for each unsupported token type, and update `.gas-snapshot` (`forge snapshot --no-match-test
   "testFuzz|invariant"`; fuzz gas is non-deterministic and excluded).
6. For secrets: assert that errors, JSON and logs do not contain key bytes (`secrets.test.ts` patterns).
7. For UI: test the component with the mocks in `apps/web/src/test/`; test the pure logic in `src/lib/` separately; add a
   Playwright case only for flows that need a real browser (CSP, storage inspection, accessibility).
8. Do not weaken a threshold or add a coverage exclusion to get green; exclusions must be justified in the package
   `DEVIATIONS.md`.

## 8. What is not tested anywhere (as of this page)

Real wallets (`eth_signTypedData_v4` UIs, hardware wallets), real RPC providers or public testnets, mainnet-fork tests,
Firefox/Safari, Mythril, mutation testing, long Echidna campaigns, the relayer Docker image and systemd unit, the release
workflows on GitHub, BlindBit against a live oracle, Bitcoin Core acceptance of spends, an external audit.
