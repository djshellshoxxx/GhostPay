## Independent PolicyAccount / factory review

Reviewed the in-progress `PolicyAccount`/`PolicyAccountFactory` security ports and their regressions. The request-destination capture is checked against the current destination before request status/limit mutation or payout; a failed check leaves the request cancelable. `SafeCast.toUint64` now guards both timelock timestamp conversions. Withdrawal execution remains nonreentrant and transfer failure reverts status/limit state atomically. Factory preconditions run before fee collection; deployment is nonreentrant; a failed transfer that changed payer/recipient balances or allowance reverts, preventing a false-return partial transfer from producing a free clone. The blacklist refusal/unchanged-state waiver is documented in `DEVIATIONS.md` P7 and covered by tests, so it is an explicit availability tradeoff.

Review finding sent to the library-QA author and fixed: after a successful `trySafeTransferFrom`, `_collectFee` now requires `payerBefore >= fee`, exact payer debit, and exact recipient credit. True-return no-debit and wrong-debit regression mocks both assert atomic rollback. Targeted Foundry verification passed: `forge test --match-contract PolicyAccountFactoryTest -vv` produced 32 passed, 0 failed, 0 skipped.
