## Result

**No new confirmed custody or signing defect was established within this scope.** All 68 focused tests passed,
with zero failures and zero skips: 11 new independent boundary probes, 38 existing native-review cases, and
19 existing review-authority cases. The web TypeScript check and the new test's type-aware ESLint check passed.
These results validate a specific implementation boundary; they do not qualify the complete product or either release.

The new tests execute the actual `createNetworkAuthority`, `createClient`, session guards, Sweep helpers,
stealth-secret derivation, EIP-1559 signing, transaction hashing, and sender recovery. The transport returns authored
JSON-RPC responses in memory. No external endpoint, browser, local development chain, or external testnet is used.
Every key generated by these tests is synthetic, and no private-key argument or secret value is included in the receipts.

## Adversarial observations

| Boundary | Independently observed result |
| --- | --- |
| Authorized native preparation and confirmation | Preparation produces no signature. Confirmation produces exactly one actual signature and one observed raw-transaction dispatch; recovered signer matches the expected stealth address. |
| Silent session clear during signing | The completed signature is discarded before the journal callback or transport. This does not depend on receiving a session notification. |
| Session suspension or replacement during signing | The completed signature cannot authorize a later handoff; derived buffers are zeroed. |
| Delayed expiry notification | The synchronous session-expiry check revokes the operation before handoff even when the expiry event was deferred until the signature continuation. |
| Network invalidation or selected-endpoint replacement during signing | The network capability refuses raw-transaction dispatch. No request reaches the synthetic transport. |
| Session revocation in the synchronous native journal callback | The native operation guard checks again before the RPC call, so the callback cannot permit a stale dispatch. |
| Session or network revocation in the ERC-20 journal callback | The actual RPC authorization guard refuses final dispatch even though the non-native helper does not use the native review wrapper. |
| Revocation after transport dispatch starts | The outcome remains `unknown-after-handoff` with the exact hash of the signed bytes. It is not falsely reported as unsent. |

The current helper deliberately treats a failure of the final RPC call as uncertain even when the in-memory
network authority rejected it before transport. Consequently, an already-created journal entry can remain locked
after such a refusal. The probe preserves this conservative behavior; it is not evidence of a transmitted transaction
or a demonstrated fund-loss vulnerability. Any future attempt to distinguish pre-dispatch refusal must preserve
the stronger requirement that an actually dispatched transaction can never be reported as unsent.
